# 汽运一期需求基准

本文档记录本项目后续汽运业务开发的已确认规则。新系统不是照搬旧系统，也不是重构交接版本，而是在交接版本基础上补齐流程、门禁、费用和复盘能力。

## 一、建设原则

1. 基于交接版本继续开发，不推倒重来。
2. 当前订单的所有工作内容都必须能从订单详情页查看、跳转和推进。
3. 一切由工作流控制：状态、下一步动作、门禁、阻断原因、负责人和待办必须来自统一规则。
4. 系统必须让业务员、操作、仓库、财务、主管、老板都能在一到两分钟内无教程看懂当前该做什么。
5. 系统可以自动生成待办和提醒，但不能自动替人做业务决策。
6. 费用最终审核、对账、收付款属于现有“费用结算”模块；订单前段只显示醒目的费用预录状态和风险入口，不拆第二套费用模块。
7. 旧系统只作为业务参考；新系统以流程清晰、模块化、结构简单、功能完整为标准。

## 二、汽运一期主流程

```text
订单创建
→ 审核分配
→ 国内执行与跟踪
→ 口岸换装与配载
→ 出境后对账
→ 收付款与结算
→ 数据与复盘
```

业务场景为：客户下单后，车队到客户仓库提货，运输到口岸，在口岸完成出入境手续、配载或整车发运，出境运输到境外目的仓，客户再到境外仓自提。

## 三、订单详情页主线结构

订单详情页顶部固定展示：

```text
订单总工作流
费用预录状态卡
费用风险卡
关键摘要
下一步动作与阻断原因
```

模块主线顺序：

```text
1. 委托信息
2. 货物信息
3. 任务分配
4. 运输安排
5. 国内仓库作业
6. 文件单证
7. 报关作业
8. 口岸配载/换装
9. 运输执行与跟踪
10. 境外仓自提
11. 费用结算
12. 异常处理
```

订单创建时勾选“委托服务”，对应服务会在订单详情页增加对应模块，并影响工作流门禁。

## 四、顶部工作流阶段

顶部工作流按八个阶段展示：

```text
1. 订单创建
2. 审核分配
3. 国内执行
4. 口岸配载
5. 出境运输
6. 境外仓自提
7. 对账结算
8. 完成复盘
```

默认一眼显示当前阶段。鼠标悬停时展开：

```text
当前模块
下一步动作
当前负责人
阻断原因
跳转入口
```

移动端用点击展开。

## 五、订单创建规则

订单创建填写客户和业务员已经敲定的内容，具体执行细节在派单和执行阶段确定。

创建订单应填写：

```text
客户
业务员
提货地址
提货联系人
预约提货时间
货物预录信息
出口口岸
境外目的仓
应收费用
应付费用或提货费
服务类型
备注和特殊要求
```

不在订单创建阶段确定：

```text
国内车队
司机
车牌
实际提货时间
到达口岸时间
实际装车结果
出境确认时间
```

草稿允许缺资料。提交审批必须满足门禁，缺项要显示清楚并支持一键跳转修复。

## 六、仓库与口岸主数据

境外目的仓必须从基础数据选择，不能只填自由文本。允许补充地址备注。

仓库主数据增加单选角色字段：

```text
国内集货仓
口岸仓
境外目的仓
```

订单创建中的“境外目的仓”下拉框只显示启用的境外目的仓。配载中的“集货仓库”只选国内集货仓或口岸仓。

出口口岸必须从口岸主数据下拉选择。订单创建页需要提供“添加口岸”“添加仓库”的入口。

新增口岸的基础字段：

```text
口岸名称
国家
城市/地区
口岸类型
状态
```

新增仓库可自动创建默认库区：

```text
国内/口岸仓：收货区、待配载区、发货区
境外目的仓：到仓区、待提货区、已预约区、异常区
```

## 七、审核与派单

未提交、未审核通过的订单不能派单。

流程：

```text
提交审批
→ 业务主管审核
→ 操作主管派单
→ 指定主操作员
```

系统可自动生成“待操作主管派单”任务，但派给谁必须由操作主管点选确认。

订单创建时可填写建议操作员或客户固定操作员，但只是建议。操作主管可以不看建议，直接指定任意有权限的操作员。

第一期一个订单只分配一个主操作员。模块负责人默认跟随主操作员。主操作员可在权限内分派模块任务，但不能更改订单主负责人；订单主负责人只能由操作主管调整。

## 八、整车与拼车规则

整车订单：一台车只装一个订单。

拼车订单：一台车装多个订单。

订单不允许拆分。同一订单的货物不能同时出现在多台车上。

如果一票订单货物不能装入任一车辆，系统必须阻断并提示：

```text
更换更大车辆
单独派车
改为整车
```

## 九、仓库实收数据

仓库负责验收货物数据是否正确。

订单创建数据只是预录和对比依据。拼车配载、车辆容量校验、成本分摊统一以仓库入仓实收数据为准。

第一期仓库实收必填：

```text
实收件数
实收重量
实收体积
包装类型
入仓时间
收货人
货物/单证照片
异常备注
```

不强制逐箱逐件全链路扫描。以下情况需要包裹明细：

```text
部分自提
异常
分批到货
多包装类型
```

实收数据与订单预录不一致时：

```text
不覆盖原订单数据
生成“实收差异确认”待办
超过阈值时客服/业务确认费用影响
仓库作业可继续
最终对账前必须处理差异
```

建议第一期差异阈值先按 5%。

## 十、拼车配载状态

拼车/配载到境外仓自提的主状态：

```text
待配载
→ 已预排
→ 已配载待出境
→ 出境运输中
→ 已到境外仓
→ 待客户自提
→ 已完成自提
```

状态含义：

```text
待配载：货已实收，可进待配载池
已预排：临时放到某台车计划里，未确认
已配载待出境：已确认装车/车次，不允许再被其他车装载
出境运输中：已录出境时间/出境确认
已到境外仓：境外仓入库确认
待客户自提：已通知客户可提货
已完成自提：货物全部提走
```

待配载池默认按以下条件分组：

```text
出口口岸
境外目的仓
国内集货仓/口岸仓
```

线路作为辅助筛选。

待配载池需要筛选按钮。默认筛选项：

```text
出口口岸
境外目的仓
国内/口岸仓
线路
```

更多筛选项：

```text
客户
业务员
操作员
货物状态
单证状态
费用差异状态
预计/实际入仓日期
重量/体积范围
```

## 十一、确认配载门禁

确认配载的阻断项：

```text
仓库实收未完成
订单拆分或重复装车
同一订单已确认在其他车辆
出口口岸缺失
境外目的仓缺失
国内/口岸仓缺失
报关/转关基础资料缺失
车辆容量不满足
```

确认配载的预警项：

```text
费用差异未确认
应收未最终确认
应付供应方不完整
货物/单证照片缺失
客户特殊要求未确认
```

预警只提醒，不自动阻断；阻断由工作流门禁决定。

## 十二、出境确认

确认配载后状态为：

```text
已配载待出境
```

录入出境确认后进入：

```text
出境运输中
```

出境确认必填：

```text
确认出境时间
出境口岸
出境车辆/境外段车牌
```

凭证照片和备注选填。

## 十三、境外仓入库与自提

境外仓入库必填：

```text
实际到仓时间
境外目的仓
实到件数
外包装状态
```

如果实到件数与出境装车件数不一致，订单可以进入“已到境外仓”，但不能进入“待客户自提”，必须先处理差异。

入库无差异后，系统自动生成“待通知客户提货”任务。客服或操作员点击“发送提货通知”后，订单进入“待客户自提”。

第一期提货通知先做：

```text
系统内通知记录
一键复制微信通知文案
```

不先接短信或邮件。

客户门户允许预约自提：

```text
提货人姓名
电话
证件号/车牌号
预约时间
备注
```

完成自提必填：

```text
实际提货时间
提货人姓名
提货人电话
提货件数
仓库经办人
签收/交接凭证照片
```

证件号、车牌号、备注选填。

提货件数等于待提件数时进入“已完成自提”。少于待提件数时进入“部分提货/待继续自提”。

境外仓免费仓储期默认 7 天。超过免仓期后，系统生成待确认滞留费提醒和费用草稿，但不自动入账。客服或财务手工确认金额后，生成应收补充费用。

## 十四、费用结算总规则

财务侧统一使用“应付往来单位”，不把供应商等同于车队。

应付往来单位角色包括：

```text
国内承运方
境外承运方
报关/转关服务商
仓库
装卸/加固服务商
代理
其他
```

费用分应收和应付：

```text
预估应收 → 确认应收 → 客户对账/收款
预估应付 → 确认应付 → 应付对账/付款
```

只有确认应收才能进入客户对账单。只有确认应付才能进入应付对账单和付款流程。

进入“出境运输中”后，系统自动生成“待发起应收对账”任务，但必须由客服或业务手动点击发起对账，系统才生成正式对账单。

客户应收对账必须要求所有应收项都是确认应收。应付未确认只做内部预警，不阻断客户应收对账。

应付对账只要求所选应付费用全部为确认应付，不要求客户应收已对账或已收款。

## 十五、对账单合并规则

客户应收对账单允许合并多票订单，条件：

```text
同一客户
同一结算主体
同一币种
已进入出境运输中
```

订单详情页发起对账时可以选择：

```text
只对当前订单生成对账单
加入该客户已有待确认对账单
```

应付对账单允许合并，条件：

```text
同一应付往来单位
同一币种
```

禁止跨往来单位合并。

对账单未确认、未收款/未付款时允许撤回重做，但必须保留日志。若已经客户确认、开票、收款、付款、核销或财务锁定，只能走费用调整、红冲或补充费用。

## 十六、费用审核与锁定

按旧系统保留：

```text
应收完成
应付完成
业务审核
财务审核
业务锁定
财务锁定
关账/封账
```

页面展示为：

```text
应收已确认
应付已确认
业务已审核
财务已审核
业务已锁定
财务已锁定
```

应收和应付可以分别完成、分别审核、分别锁定，不要求同步。

业务锁定后，业务/操作不能直接修改原费用行，只能走费用调整或补充费用。

财务锁定后，费用、对账、付款、核销结果原则上不能修改，只能由财务权限解锁或走调整流程。

费用调整/补充费用必须区分：

```text
应收调整
应付调整
```

调整记录必须保留：

```text
调整原因
操作人
时间
审批记录
```

调整后的费用重新参与毛利、对账、收付款和复盘统计。

## 十七、发票规则

按旧系统分两类：

```text
客户开票记录（销项）
供应方收票记录（进项）
```

发票记录必须从已确认/已审核的费用行生成，不能脱离费用单独创建。

生成发票记录时，所选费用行必须满足：

```text
同一往来单位
同一所属公司
同一币种
```

否则禁止合并生成一张发票。

支持部分开票和部分收票。费用行显示：

```text
费用金额
已开票/已收票金额
未开票/未收票金额
```

累计开票/收票不能超过费用金额。

第一期不接税控或自动开票接口，但需要保留旧系统核心字段和校验：

```text
开票/收票公司
发票类别
发票号码
发票代码
开票日期
税率
抬头/销方
税号
地址电话
开户行账号
币种
金额
汇率
备注
附件
```

## 十八、收付款与核销

客户收款支持：

```text
部分收款
多次收款
一笔收款核销多条应收费用
```

供应方付款支持：

```text
部分付款
多次付款
一笔付款核销多条应付费用
```

核销必须满足：

```text
同一往来单位
同一币种
```

累计收款不能超过应收金额。累计付款不能超过应付金额。

收付款记录允许先独立录入，后续再匹配核销到费用：

```text
先录银行收款/付款流水
→ 后续选择对应应收/应付费用
→ 核销
```

独立录入收付款记录第一期必填：

```text
往来单位
收/付款方向
币种
金额
收/付款日期
所属公司
银行账户/现金账户
经办人
```

凭证附件、备注选填。

费用行和收付款记录都必须显示未核销余额：

```text
费用行：应收/应付金额、已核销金额、未核销金额
收付款记录：流水金额、已分配金额、未分配余额
```

## 十九、费用风险卡

订单详情页顶部需要费用风险卡，提醒：

```text
毛利为负
应收未确认
应付未确认
客户未回款但已申请付款
费用超过预估
费用未锁定
```

费用风险卡只做提醒，不自动阻断业务流程。真正阻断仍由工作流门禁控制。

## 二十、拼车成本分摊半自动模块

拼车成本分摊仅影响内部毛利，不影响客户应收。客户应收由商务定价和货物数据变动确认决定。

成本分摊以装车整车实收数据为准，不以下单预录数据为准。

成本分摊第一期按半自动模块设计：

```text
系统生成建议分摊结果
→ 操作/财务人工检查
→ 可手工修改分摊金额或分摊比例
→ 填写调整原因
→ 人工确认后才生成正式应付分摊费用
→ 正式费用进入应付完成、业务审核、财务审核、锁定流程
```

在人工确认前，系统生成的分摊结果只能是“建议结果/草稿”，不能入账，不能进入应付对账，不能参与正式付款。

重抛比按 1:300 判断，仅用于生成建议分摊结果。

暂定规则：

```text
整车重量 / 整车体积 < 300：按体积分摊
整车重量 / 整车体积 >= 300：按重量分摊
```

按重抛比分摊的费用：

```text
运费
装卸费
加固材料费
```

按票数均摊的费用：

```text
转关费
报关费
入仓费
```

注意：加固材料费在旧沟通中出现过分类不一致，后续需要专业人员最终确认。

示例：

```text
整车重量 23753 kg，体积 132 cbm
23753 / 132 = 179，小于 300，按抛货处理
运费 = 3000 USD × 每个订单体积占比
报关费：一车 10 票，总费用 (400 + 9 × 100) / 10
```

建议分摊结果页面必须显示：

```text
配载批次
车辆/车牌
参与订单
每票订单实收重量
每票订单实收体积
整车实收重量
整车实收体积
重抛判断结果
费用项
费用总额
建议分摊方式
建议分摊比例
建议分摊金额
人工调整金额
调整原因
确认人
确认时间
```

人工确认前允许重新计算。人工确认后不允许直接覆盖原结果，只能走费用调整、红冲或补充费用。

## 二十一、列表与待办

以下核心列表默认显示“下一步动作”和“当前负责人”：

```text
订单列表
运单列表
配载池
费用列表
首页待办
```

首页待办、订单详情顶部、订单列表里的“下一步动作”必须是同一句话，并由同一套工作流计算。

下一步动作必须同时显示阻断原因。例如：

```text
下一步：提交审批
阻断：缺境外目的仓、缺应收费用、缺应付费用

下一步：确认配载
阻断：订单 A 未入仓实收、订单 B 缺报关资料
```

每个阻断原因必须提供一键跳转到修复位置：

```text
缺境外目的仓 → 委托信息
缺费用 → 费用预录卡/费用结算模块
缺实收数据 → 仓库入库记录
缺报关资料 → 文件单证/报关作业
缺出境确认 → 运输跟踪/出境确认
```

## 二十二、数据与复盘

第一期只做订单级复盘，不做复杂经营 BI。

每票订单完成后沉淀：

```text
时效：下单、提货、入仓、配载、出境、到仓、自提完成
货量：预录 vs 实收 vs 装车
费用：应收、应付、实收、实付、毛利、毛利率
异常：货差、延误、费用调整、客户异议
人员：业务员、主操作、仓库经办、财务经办
```

费用结算毛利统计按旧系统保留：

```text
应收
应付
实收
实付
毛利
毛利率
```

并支持按币种分别统计。

## 二十三、订单完成状态

订单最终完成条件：

```text
货物已完成自提
应收应付状态无未处理阻断项
订单复盘已生成
```

不强制所有款项都已收已付才能业务完成。若仍有未收款或未付款余额，订单显示：

```text
业务完成，结算未闭环
```

并继续生成财务待办。

结算全部闭环后，订单进入最终状态：

```text
已完成并结清
```

## 二十四、后续待确认问题

以下问题尚未完全闭合，开发时不能写死为不可改规则：

1. 拼车成本分摊最终公式需要专业人员确认，尤其是按体积、按重量、按计费重量还是其他口径计算订单占比。
2. 加固材料费归类未闭合：旧沟通中同时出现过按重抛比分摊和按票数均摊两种说法。
3. 拼车分摊中哪些费用项进入“按重抛比分摊”，哪些进入“按票数均摊”，需要形成费用项配置表。
4. 分摊费用存在不同币种时，是否允许同车分摊，使用哪个汇率日期，需要财务确认。
5. 人工调整分摊结果的权限、是否需要二次审核、调整幅度超过多少触发预警，需要确认。
6. 费用超过预估的预警阈值未确认，暂时只能做“超过即提醒”或使用系统默认阈值。
7. 不同客户、仓库、线路的境外仓滞留费计费标准未确认，第一期只做超期提醒和手工金额确认。
8. 客户货物数据变动多大才必须重新确认应收，当前建议阈值为 5%，仍需业务确认。
9. 发票字段是否完全覆盖旧系统字段，实施前需结合当前交接版本的数据表做最小字段映射。
10. 业务锁定、财务锁定的解锁权限和审批流需要结合现有角色权限表确认。
11. 各角色的最终权限边界需要在开发前按岗位表落地，尤其是费用、客户资料、利润、统计分析的查看限制。
12. 境外仓客户自提的证件号、车牌号是否在某些客户或仓库变为必填，需要运营确认。
13. 旧系统中的 `Carrier`、`LrCarrier` 等字段在新系统中对应国内承运方、境外承运方还是统一承运方，需要做字段映射。
14. 订单完成后存在未收未付余额时，哪些余额属于“阻断项”，哪些只是财务待办，需要财务最终确认。
