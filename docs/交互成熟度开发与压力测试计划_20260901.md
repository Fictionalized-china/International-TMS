# International TMS 交互成熟度开发与压力测试计划

更新时间：2026-09-01

## 一、目标

本轮以电脑端浏览器的生产系统为唯一目标，统一管理后台、客户门户和仓库端的设计语言，并确保：

1. 操作有即时、对象级、可恢复的反馈。
2. 不可逆操作具备分级确认、审计和服务端幂等保护。
3. 整车与拼车绑定各自最新已发布工作流，订单与配载单不存在双向争抢控制权。
4. 高频业务尽量在工作台、详情抽屉和右侧上下文区就地完成，减少跳转和翻页。
5. 压力测试覆盖读取、写入、重复提交、批量推进、跨订单同步和异常恢复。

## 二、实施批次

### 批次 A1：安全与确定性底座

- 全局请求进度、超过 2 秒的等待升级提示和无障碍播报。
- 弹窗焦点圈闭、焦点归还、背景误触保护和脏数据关闭确认能力。
- 危险操作确认组件，支持输入确认词的极高风险模式。
- 三端静态“同步正常”改为网络、同步中和最后页面更新时间的真实状态。
- 错误边界提供重试、返回和回到工作台入口。

### 批次 A2：工作流与数据控制权

- 工作流版本影响预览、发布二次确认和变更审计。
- 订单详情展示当前推进主体、门禁、资料补录和配载单入口。
- 配载阶段由配载单原子同步子订单，订单对应区域只读。

### 批次 A3：领域工作台与键盘流

- 询价报价连续 Enter 输入与工作流版本抽屉。
- 订单、配载、仓库扫码的就地处理和错误字段自动聚焦。
- 紧凑/舒适密度、统一状态字典和不少于 12px 的辅助文字基线。

### 批次 A4：稳定性与压力测试

- 单元测试、类型检查、生产构建、真实浏览器主流程。
- HTTP 读取压力、写入并发、重复提交、跨订单批量推进和长时间稳定性。
- 对崩溃、数据库锁、无限等待、重复记录和流程无法推进建立回归用例。

## 三、每批出口

每批必须依次通过：目标测试、全量 Vitest、类型检查、生产构建、差异检查，并创建独立本地 Git 提交。最后执行压力测试矩阵；出现异常时先形成可重复失败信号，再修复并回归。
