# International TMS 交互成熟度开发与压力测试计划

更新时间：2026-09-01

## 一、目标

本轮以电脑端浏览器的生产系统为唯一目标，统一管理后台、客户门户和仓库端的设计语言，并确保：

1. 操作有即时、对象级、可恢复的反馈。
2. 不可逆操作具备分级确认、审计和服务端幂等保护。
3. 整车与拼车绑定各自最新已发布工作流，订单与配载单不存在双向争抢控制权。
4. 高频业务尽量在工作台、详情抽屉和右侧上下文区就地完成，减少跳转和翻页。
5. 压力测试覆盖读取、写入、重复提交、批量推进、跨订单同步和异常恢复。

## 二、实施批次

### 批次 A1：安全与确定性底座

- 全局请求进度、超过 2 秒的等待升级提示和无障碍播报。
- 弹窗焦点圈闭、焦点归还、背景误触保护和脏数据关闭确认能力。
- 危险操作确认组件，支持输入确认词的极高风险模式。
- 三端静态“同步正常”改为网络、同步中和最后页面更新时间的真实状态。
- 错误边界提供重试、返回和回到工作台入口。

完成情况：已完成。管理后台、客户门户和仓库端已接入真实连接/页面更新时间；报价撤回、报价作废、会话撤销以及工作流节点、模组、办理步骤、字段删除已接入统一确认弹窗。

验证记录：

- `npm run ci`：通过；29 个测试文件、113 项测试通过，类型检查和生产构建通过。
- 生产构建浏览器预览：通过；1440×900 下动态同步状态可见，控制台 0 error / 0 warning。
- 危险确认弹窗：通过；默认焦点落在确认动作，Tab 焦点圈闭有效，Escape 关闭后焦点返回原按钮，未执行测试数据变更。
- 离线状态：通过；浏览器断网后立即显示“离线，当前数据可能已过期”，恢复在线后重新显示页面更新时间。

### 批次 A2：工作流与数据控制权

- 工作流版本影响预览、发布二次确认和变更审计。
- 订单详情展示当前推进主体、门禁、资料补录和配载单入口。
- 配载阶段由配载单原子同步子订单，订单对应区域只读。

完成情况：已完成。

- 已使用的工作流仅允许调整字段/文件的可填、必填、隐藏状态并增加字段或文件，禁止新增节点；未使用版本仍可维护结构。
- 拼车、整车分别选择各自最新已发布版本，报价页保留显式版本选择；切换版本前展示受影响节点、门禁和补录任务，并要求发起账号二次确认。
- 执行规则采用“历史节点不回退、按订单阶段分层生效、隐藏数据永久保留审计痕迹”。已跨过阶段的新必填项生成订单详情右侧补录任务，不倒退订单状态。
- 配载单成为拼车出口准备、装车出库、报关出境、海外仓收货的唯一写入入口，并以事务方式同步子订单；异常支持配载单、订单、运输单元三级范围。
- 工作流变更、补录任务和异常处理均写入站内通知；邮箱和短信保留后续接口，不作为本轮门禁。

验证记录：工作流编辑策略、版本切换策略、订单阶段推进、报关放行集合、配载异常门禁和子订单同步测试全部通过；并发异常创建/解决未产生重复记录。

### 批次 A3：领域工作台与键盘流

- 询价报价连续 Enter 输入与工作流版本抽屉。
- 订单、配载、仓库扫码的就地处理和错误字段自动聚焦。
- 紧凑/舒适密度、统一状态字典和不少于 12px 的辅助文字基线。

完成情况：已完成。

- 管理后台、客户门户和仓库端统一接入紧凑/舒适密度、功能动效开关和快捷键帮助，偏好在浏览器刷新后保留。
- `/` 定位当前页面的高频搜索框；明确标记的录入表单支持 `Ctrl/Cmd + Enter`；弹窗支持焦点圈闭、Escape 关闭和焦点归还。
- 报价、订单、配载、仓库验收和异常处理尽量在当前工作台、详情抽屉或就地窗口完成，避免为修改单一状态跳转详情页。
- 危险操作统一使用确认弹窗；服务端改为显式目标状态和条件更新，避免重复点击导致状态来回翻转、重复订单或重复审计。

验证记录：1600×1000 桌面浏览器下三端布局、搜索快捷键、偏好持久化、必填校验保护和控制台均通过；三端控制台 0 error。

### 批次 A4：稳定性与压力测试

- 单元测试、类型检查、生产构建、真实浏览器主流程。
- HTTP 读取压力、写入并发、重复提交、跨订单批量推进和长时间稳定性。
- 对崩溃、数据库锁、无限等待、重复记录和流程无法推进建立回归用例。

完成情况：已完成。

- 最终 `npm run typecheck` 通过；Vitest 32 个测试文件、126 项测试全部通过；生产构建通过。
- 写入并发覆盖：配载异常创建/解决、配载单整单取消、至少保留两票的并发移单、报价撤回/重新接受、联系人/地址删除、承运商/车辆/司机状态更新。结果均为单一胜者、单一审计和确定性最终状态。
- 生产预览基础压力：40 并发、1000 次请求，1000 成功、0 失败，P95 804.4ms，最大 852.2ms。
- 生产预览强化压力：50 并发、2000 次混合请求，2000 成功、0 失败，吞吐 51.68 次/秒，P95 1012.9ms，最大 1129.6ms。
- 本地 HMR 开发服务器在 40 并发下出现随机 `Miniflare/Undici fetch failed`，且失败随机落在不同路由、发生于应用路由执行之前；同一生产构建未复现。结论：开发服务器只用于热更新调试，压力验收以生产构建预览为准。

最终结论：本轮范围内未发现业务死锁、死循环、无限等待、重复创建、并发状态翻转或流程门禁无法推进；生产构建压力矩阵无异常。

## 三、每批出口

每批必须依次通过：目标测试、全量 Vitest、类型检查、生产构建、差异检查，并创建独立本地 Git 提交。最后执行压力测试矩阵；出现异常时先形成可重复失败信号，再修复并回归。
