# 云端稳定性修复与验收

## 范围与边界

- 仅处理现有已实现功能；不新增司机抢单、GPS、围栏等功能。
- 不单独调整订单，不重置账号，不改业务流程配置与岗位分配。
- 保留老板的全权办理能力；老板也不能绕过金额、终态和并发一致性约束。
- 禁止以单元测试通过替代线上运行验证。

## 本批修改

1. 旧订单操作 URL 转到现有、带财务权限过滤的订单详情，关闭旧运输档案写接口；保留档案查询。
2. 新增通用数据库提交守卫；条件更新失败在事务内回滚历史、责任人及后续写入。MySQL 同连接额外校验，兼容非严格模式。
3. 仓库扫码限制当前仓库，盘点扫码/结束使用版本校验和原子合计；移库重查状态与原库位。
4. 财务对账与发票登记按固定费用顺序锁定，再于事务内重验资格和余额；确认对账增加提交守卫。
5. 发票登记新增请求标识与内容摘要，相同提交可恢复结果，不重复占额。
6. 文件解析同时支持已有 Base64 附件与 URL 编码的系统 HTML 单据；HTML 文档增加沙箱。
7. 修复计费进位浮点误差、CBM 单位被忽略、多段续重断档及非有限数。
8. 计划时间统一解析北京时间旧输入、明确偏移时间和 UTC 数据库时间；新计划校验先后关系，单据显示北京时间。保留旧请求摘要兼容性。

## 自动验证

- 对修复前的文件/计费缺陷新增测试并确认失败，再修复至通过。
- SQLite 实际事务验证零行更新回滚、仓库跨仓拒绝、关闭盘点后续扫拒绝、出库后移库拒绝。
- 全迁移真实测试库验证发票重复提交复用结果、余额变化回滚发票头与分摊。
- MySQL 适配器验证提交守卫同连接执行、非严格模式失败回滚。
- 云端 MySQL 通过连接级临时表验证 prepared ROW_COUNT 成功、零行回滚及 matched-row 语义；不修改生产业务数据。
- 发布前运行完整测试、TypeScript 检查、MySQL 兼容扫描及生产构建。

实际结果：243 个测试文件、1,463 项测试全部通过；`npx tsc -b`、`npm run build:mysql` 通过。严格模式数据库守卫异常也已转换为可识别的状态冲突，避免原始数据库错误直接暴露。

## 人工验收标准

1. 老板正常录单、审批、办理；业务员/操作/单证不能通过旧 URL 看到未授权成本毛利。
2. 同一订单两窗口同时推进，最多一个成功；失败窗口提示刷新，无多余历史或错误负责人。
3. 同一发票提交重试，仅一条发票及一套分摊；合法不同请求仍允许部分金额分次登记。
4. 仓库 A 扫仓库 B 标签被拒；盘点结束后旧窗口不能补写；已出库包裹不能移库。
5. 配载单、装车清单及批次运单可打开；既有上传 PDF/图片仍可打开。
6. 0.07 KG 按 0.01 KG 进位仍为 0.07；2 CBM 按每 CBM 10 元收费为 20；续重区间断档不返回错误报价。
7. 相同计划时间在本地与云端预警一致；计划装车晚于出境/到仓被拒绝。

## 部署与回滚

- MySQL 新增迁移 182：只增加守卫表、盘点版本列、发票幂等列与唯一索引，不改已有订单状态或金额。
- 使用现有阿里云发布脚本；先保存数据库、环境配置与旧发布路径，再迁移和切换。
- 发布前后对账号、订单、费用核心数据计算摘要，必须不变。
- 检查 readiness=182、公网登录及现有各端只读页面；失败回退旧应用，不以反复改订单解决。
- 新增列允许为空或有默认值，旧程序回滚兼容；数据库备份单独保留。

## 尚不能承诺

自动测试与有限线上检查不能证明所有并发、所有历史数据组合永远不出错；未覆盖的异常应通过日志与明确回归案例继续修复，不能通过放宽权限或跳过门禁掩盖。
