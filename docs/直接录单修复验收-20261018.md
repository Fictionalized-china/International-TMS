# 直接录单修复与验收（2026-10-18）

## 根因与范围

1. 云端只读核实：当前发布的整车、拼车工作流均已停用 `quotation / quote.created`，启用 `order_creation / order.created`。录单 action 却仍以 `quote.created` 初始化，收不到实例后抛出“所选工作流缺少可用于录单的初始节点”，并清理刚写入的报价。这是配置组合下可重复触发的问题，不是仅业务员没有权限。
2. action 错误结果缺少 `entryMode`，弹窗内错误筛选不匹配，提示落在遮罩后的页面。
3. 真实全迁移 SQLite 测试发现，建单后的 `acceptance_source='offline_order_entry'` 不符合数据库只允许 `admin/portal` 的约束，可能已建单却返回失败。线上 MySQL 是否启用了同一 CHECK 不作推断；修复不再依赖此非法值。
4. 直接录单页只有启动弹窗和页头，关闭弹窗未定义返回位置，留下空壳页。

## 修改

- 直接录单使用订单创建事件；辅助报价在报价节点停用时，允许从已配置的订单初始节点冻结流程。
- 不恢复已停用节点、不跳过委托资料补充与审批、不放宽费用和岗位权限。不修改任何现有订单或线上业务配置。
- 保持接受来源为 `admin`；直接录单通过请求标识、摘要与审计动作识别。保留相同请求重试复用订单、不同内容拒绝覆盖的保护。
- 错误结果携带入口模式，弹窗显示失败原因并保留已填内容。
- 关闭弹窗并确认放弃后返回订单台账；成功后进入新订单详情；跳转保留当前 `itmsTab`，避免串号或丢登录。

## 我方唛头联系人

用于货物唛头上的我方业务/异常联系信息，可选择最多三人，生成订单时保存姓名、岗位及电话快照，后续组织资料改变不随意改写历史标签。不是客户联系人，也不决定订单办理权限。

当前整车、拼车配置为选填；不选不应阻断录单。是否必填仍服从工作流字段配置。

## 人工验收

1. 业务员进入订单中心直接录单，拼车登记提货费（自送可填 0）、客户应收与必要资料，保存后进入新订单详情；停留在委托资料补充，不提前审批。
2. 整车要求的六类费用仍受配置控制，同类费用可多条；缺必要费用时弹窗明确提示，补齐可重试。
3. 不选唛头联系人仍能保存；需要外显电话时再选我方人员。
4. 空表点叉返回台账；有改动时先确认放弃，取消放弃则继续填表。
5. 网络重试原请求不重复建单，不覆盖此前成功的订单。
