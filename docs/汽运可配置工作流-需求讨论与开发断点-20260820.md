# 汽运可配置工作流：需求讨论与开发断点

更新时间：2026-08-20

## 当前决定

本轮暂停代码实现，继续通过问答整理完整需求。岗位权限限制功能可以开发，但暂不正式限制现有账号；工作流和模组配置不属于该暂缓范围。

## 已确认的目标结构

1. 系统采用“业务对象主表单 -> 工作流节点 -> 业务模组 -> 字段与动作”的四层结构。
2. 老板可在不修改代码的情况下新增、停用、插入和移动节点、模组及自定义字段。
3. 已发布且被订单使用的内容只能停用，不能物理删除；旧订单绑定原工作流版本。
4. 权限分为查看、编辑、审核、推进、回退和数据范围六类，按岗位提供默认值，并允许有审计记录的账号例外。
5. 权限启用分为“不限制、模拟、正式限制”三级；当前先开发，暂不正式限制。
6. 节点完成状态统一由字段、模组和门禁计算；事实型动作可自动完成，审批、派单、配载、放行、出库和出境等业务决策必须人工确认。
7. 相同业务数据只保存一次，其他模组引用，不重复录入。
8. 工作流支持主线、条件分支、可选节点和分支合并，不开放任意循环脚本。
9. 订单页面采用高信息密度主表单；同类信息对齐，当前操作固定可见，减少滚动和跳转。
10. 主要操作路径为“岗位门户高密度表格 -> 订单或PZ主表单 -> 当前节点模组”。

## 已确认的整车与拼车分支

1. 整车或拼车由已接受报价确定，后续不能直接改变。
2. 两类订单分别完成国内运输和国内仓入库、清点、货齐确认。
3. 国内仓确认货齐后确定汽运线路、出境口岸和起运地清关地。
4. 整车以订单号作为境外运输追踪主控对象。
5. 拼车在订单详情的小配载工作台选择兼容订单，确认后才生成正式PZ配载单。
6. 不设置临时预排。重量、体积及能否装下由操作员人工判断。
7. PZ生成后再安排承运商、车型、车辆和司机。
8. 拼车从装车出库到境外仓入库均由PZ统一推进全部子订单。
9. 境外仓逐票核对并确认整批入库后，PZ拆回各子订单，分别通知、自提和签收。
10. 重新配载会作废原PZ并生成新PZ；保留原记录。已经出境后只能走异常处理。

## 暂停时验证状态

- `npm run typecheck`：通过。
- `npm test -- --run`：24个测试文件、75项测试通过。
- `npm run build`：未通过，不能视为完成。
- 本地5189开发服务：已停止。

构建阻断：`admin.order-module.tsx` 的客户端产物错误保留了 `cloudflare:workers` 导入。触发点与同一共享模块中同时引用客户端汇总函数和服务端 `loadingCompatibilityKey` 有关。

## 恢复开发的第一步

1. 不重新分析需求，先阅读本文件和本轮后续问答结论。
2. 在 `admin.order-module.tsx` 中取消服务端对共享 `loadingCompatibilityKey` 的跨边界引用，或把服务端兼容键计算移动到独立 `.server.ts` 文件。
3. 重新运行 `npm run build`，确认 `cloudflare:workers` 不再进入客户端产物。
4. 核对PZ和整车运输单SQL的字段数、占位符数以及本地0081迁移。
5. 需求问答结束并得到明确开发指令前，不继续完善或提交本批代码。
