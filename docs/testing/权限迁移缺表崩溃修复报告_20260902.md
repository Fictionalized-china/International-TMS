# 权限迁移缺表崩溃修复报告（2026-09-02）

## 结论

本次故障与古早订单、测试数据量或系统代码体积无关，因此未删除任何订单。根因是本地开发服务早于权限迁移启动，之后热更新加载了新版鉴权代码，但运行进程仍处于旧数据库结构，查询 `membership_permission_overrides` 时触发 SQLite 缺表异常。

## 修复

1. `dev`、`dev:win` 启动前强制执行本地迁移；迁移失败则不启动服务。
2. `deploy` 调整为先执行远程迁移，再构建和发布；迁移失败则停止部署。
3. 会话鉴权在权限覆盖表短暂不可用时降级为岗位角色权限，保留登录和工作台可用性，不吞掉其他数据库错误。
4. 角色权限、用户和岗位写入前检查权限模型结构；数据库未升级时改为只读提示，禁止半迁移状态写入。
5. 全局错误页不再向界面展示 SQL、文件路径和调用栈；数据库版本不一致时显示可理解的恢复说明，详细错误只进入服务日志。
6. 已重启本地开发服务，启动日志确认数据库无待执行迁移。

## 同类风险扫描

- 新增表 `membership_permission_overrides` 的运行时读取点：会话鉴权、角色权限页面。两处均已添加保护。
- 新增字段 `roles.status` 的管理入口：角色权限、用户管理、岗位管理。写入入口均已添加结构就绪检查。
- 初始化入口由启动/部署顺序保护，避免新版程序先于数据库结构发布。
