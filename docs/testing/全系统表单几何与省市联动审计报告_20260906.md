# 全系统表单几何与省市联动审计报告

## 一、审计结论

本轮按统一设计契约处理管理后台、仓库工作台、客户门户、登录/注册/初始化页及弹窗表单：

- 单行文本框、数字框、日期时间框和原生单选下拉框使用同一高度；紧凑密度下为 `32px`，切换系统密度时共同跟随同一变量变化。
- 多行文本框与多选框固定为单行控件的三倍高度；紧凑密度下为 `96px`，禁止人工拖拽破坏行列对齐，内容超出时在框内滚动。
- 表单网格统一从顶部对齐，校验说明在控件下方增长，不再把同一行的相邻控件上下推移。
- 控件宽度分为微型 `8rem`、短型 `12rem`、中型 `18rem`、长型 `26rem` 和可伸展型。数量、币种、状态等短值不再无条件占满整列；人员、客户、订单等长选项保留更大的可读宽度；名称、地址、说明和搜索条件允许按容器伸展。
- 组织负责人、报价地区、联系人组合框和客户业务身份等自定义单值控件与原生输入框保持同一外部高度。

## 三、宽度规则

宽度同时参考字段容器语义和字段名称，后者用于补齐大量历史页面未标注宽度等级的问题。

| 宽度档位 | 典型字段 |
| --- | --- |
| 微型 `8rem` | 件数、数量、排序号、币种、分页条数、邮编 |
| 短型 `12rem` | 金额、重量、体积、比例、状态、类型、方式、范围、严重等级、是/否类选项 |
| 中型 `18rem` | 日期时间、编号、电话、国家、省州、城市、岗位 |
| 长型 `26rem` | 客户、订单、人员、仓库、承运商等实体选择 |
| 可伸展 | 名称、地址、搜索、描述、备注等可能包含长文本的字段 |

窄屏下所有控件仍以 `max-width: 100%` 收缩，不制造横向溢出。

## 四、省市联动调查

### 代码行为

客户表单的地区联动由 `PickupAddressFields` 自己维护国家、省州、城市三个局部状态：

- 改国家：只清空省州和城市。
- 改省州：只清空城市。
- 改城市：只更新城市。

该组件没有调用 `form.reset()`，没有修改父表单 `key`，也没有触发表单提交，因此按设计不会清空客户名称、联系人、电话、邮箱或详细地址。

报价页面的三级地区选择也遵循相同原则，只清空当前选择的下级地区。客户切换时重置“起运地区”属于显式业务设计，因为起运地区默认继承所选客户的提货地址；不会重置其他报价字段。

### 浏览器复现结果

使用真实 Chromium 页面、独立窗口会话和键盘输入，在“新增客户”弹窗先填写客户名称、简称、联系人、电话和邮箱，再选择省州及城市。切换完成后五项输入的实时 `value` 全部保持不变。

此前出现“整表重置”的判断来自测试脚本读取 `getAttribute("value")`：React 输入框的当前值存放在 DOM 属性 `element.value` 中，HTML 初始属性不一定同步更新，因此会把“属性仍为空”误判为“用户输入被清空”。这属于自动化取值方法错误，不是产品设计问题，也不是当前页面 bug。

## 六、人工验收建议

人工验收优先抽查以下高密度页面：报价创建/补充配置、订单各节点表单、配载单详情、仓库入库/出库、费用结算、工作流字段配置和客户档案弹窗。

检查时重点观察：

1. 同一行输入框与下拉框上下边缘是否一致。
2. 文本域是否固定为三倍高度，内容过多时是否在框内滚动。
3. 币种、状态、件数等短字段是否保持紧凑。
4. 客户、订单、人员等长选项是否仍能辨认主要内容。
5. 选择国家、省州、城市时，是否只清空不再合法的下级地区。

若人工验收发现某个特定字段的实际内容长度与当前档位不匹配，应按字段语义单独调整其档位，不再为整个页面另设一套高度或随意拉满整列。
