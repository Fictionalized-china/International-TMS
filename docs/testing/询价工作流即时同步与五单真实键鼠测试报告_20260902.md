> 日期：2026-09-02
>
> 性质：开发自测与缺陷修复记录，不替代用户最终验收
>
> 范围：管理后台、客户门户、国内仓库端；整车与拼车工作流；询价字段、文件门禁、配载及订单回显

## 一、结论

本轮确认原现象属于缺陷：询价报价页已有大量原生输入项，但工作流第一节点“询价报价”没有完整字段目录，导致老板无法按整车/拼车分别配置这些字段的必填、选填、隐藏，页面与工作流配置并非同一事实来源。

缺陷已修复，并完成同类问题扫描。最终结果如下：

- “询价报价”作为整车、拼车工作流第一节点，现显示 19 个原生字段，其中当前默认 16 个必填、3 个选填。
- 报价弹窗会随“整车/拼车”和所选工作流版本即时切换字段；保存后的报价使用自己的工作流实例快照，不被以后新报价的默认版本串改。
- 已使用工作流仍可修改字段必填、选填、隐藏；变化只对当前及未来节点生效，历史节点不回退，隐藏数据与附件保留审计痕迹。
- 委托书必填改选填后，既有订单的系统缺失阻断与补录任务会即时解除；选填改必填后，会即时产生补录阻断。
- 人工异常、仓库异常不会被字段规则重算误清除；已完成模块不会因后续规则变化被回退。
- 配载文件、待装车文件、仓库验收、PZ 资源、计划时间、装车扫码和交接备注均改为读取同一工作流实例策略，不再各自硬编码。
- PZ 的承运商、车型/车牌、司机/电话会在所有关联订单的管理端详情中直接读取同一批次事实并显示，不复制出多份易漂移数据。
- 最终真实浏览器键鼠用例 5/5 通过；全量单测 200/200 通过；类型检查和生产构建通过；本地生产构建压力测试 2000/2000 成功。

## 二、主要原因与修复

### 1. 询价原生字段没有进入工作流字段目录

原报价表单由页面硬编码字段组成，而工作流配置只认识少量自定义字段，造成“页面有字段、工作流里没有字段”。本次建立统一的询价原生字段目录，并为历史工作流版本及报价实例回填字段规则。

报价创建、编辑、客户确认和订单生成现在共同遵守以下规则：

- 先由订单类型自动选择整车或拼车工作流最新版；仍可在报价弹窗中手动选择同类型版本。
- 页面仅渲染当前版本中非隐藏字段；必填由当前实例规则决定。
- 报价保存时固化字段值与实例规则；编辑既有报价时不偷换为最新版。
- 服务端再次校验字段、费用行归属及必填完整性，不能只靠前端隐藏绕过。

### 2. 字段状态变化没有完整重算运行态

过去字段规则变化主要改变配置记录，没有统一重算订单模块状态、补录任务和门禁，因此可能出现界面已经显示“选填”，模块仍被旧缺失原因阻断，或反过来显示“必填”但没有产生阻断。

现新增统一重算服务：

- `required → optional/hidden`：仅清除该系统规则产生的缺失阻断，并关闭对应旧补录任务。
- `optional/hidden → required`：对当前及未来阶段产生系统补录阻断。
- 选填附件待审不会阻止 documents 模块完成；必填附件仍以“存在且已通过”为完成条件。
- 人工异常、仓库异常及其他人工阻断不被覆盖。
- 更新字段规则加入乐观并发校验，避免两个页面静默互相覆盖。

### 3. 仓库与 PZ 页面存在同类硬编码

扫描发现并修复以下同源问题：

- 待装车文件 SQL 遗漏了可配置的合同文件。
- PZ 创建页固定要求承运商、车辆、司机和计划时间，没有读取组合订单的工作流规则。
- 扫码确认虽可配置，出库仍固定要求全部扫码。
- PZ 交接备注只读取代表订单规则，没有聚合全批次订单。
- 仓库上传自动审核后，没有统一重算订单 documents 模块状态。
- 管理端订单详情没有展示 PZ 已保存的承运商、车辆和司机。

PZ 聚合规则现为：任一参与订单当前/未来阶段要求必填，则批次必填；没有必填但任一可见，则为选填；全部隐藏才隐藏。选填或隐藏的高风险运输信息缺失时允许继续，但必须页面二次确认并写审计；必填缺失仍强阻断。

### 4. 测试中发现的稳定性缺陷

- 文件上传后页面曾永久显示“正在处理”。根因是全局 `Modal` 的关闭副作用依赖每次渲染都会变化的内联回调，形成状态更新循环。现改用稳定引用，打开/关闭只响应信号值变化。
- 最终回归第一次重跑时捕获到 `admin.order-module.tsx` 模块连续 500。根因是一个已经不用的 `.server` 导入残留在同时导出客户端组件的路由中，导致 React Router 客户端拆包失败。移除残留导入后模块请求恢复 200，生产构建亦通过。

## 七、边界与用户验收建议

本轮没有执行远程部署、远程数据库迁移或生产环境压力测试。建议用户验收时重点复查：

1. 整车、拼车工作流“询价报价”节点是否均能看到并编辑 19 个字段规则。
2. 在另一个浏览器窗口修改委托书规则后，已打开订单刷新时门禁与补录区是否符合预期。
3. PZ 三票文件矩阵是否只阻断当前有效必填项。
4. 三票订单详情是否显示同一 PZ 的承运商、车牌/车型、司机/电话。
5. 上传文件完成后弹窗是否立即结束处理状态，不再卡死。
