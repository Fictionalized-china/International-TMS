# 真实业务全流程测试报告（企业创建至动态工作流门禁）

## 1. 测试结论

本轮已按真实业务顺序完成企业建档、联系人与地址补充、临时长沙提货地址报价、报价接受、订单生成、执行中工作流字段模式调整，以及未使用工作流新增节点、字段、校验和发布。

核心数据主线可以运行：企业、联系人、常用地址、报价、临时提货地址和订单之间能够形成有效关联；临时长沙提货地址随本次报价进入订单，未被静默写入客户常用地址簿。执行中订单的字段快照会随着工作流字段“必填/选填”调整而同步，测试结束后共享标准工作流已恢复原始配置。

当前仍有两项会直接影响预期业务操作的缺口：

1. 询价报价弹窗没有工作流/版本选择，订单详情也没有可见的工作流切换入口。新发布的工作流虽然能由底层引擎生成实例，但正常业务人员无法把它选给报价或订单。
2. 订单详情只能选择已登记的司机和车辆，不能在当前订单内就地新建未登记司机、车辆。

因此，本轮结论为：**主业务数据链路通过，动态字段门禁同步通过；工作流自由选版、新节点正常投产入口和运输资源就地新增未达到验收要求。**

## 5. 缺陷清单

### D-01 报价缺少工作流和版本选择

- 严重度：P1
- 现状：报价弹窗没有工作流字段；接受报价时服务端按业务类型自动选择默认流程。
- 影响：无法按客户、线路或合同选择新的已发布版本；工作流编辑器发布的新流程无法进入正常业务。
- 建议：报价选择业务类型后加载兼容、已发布、有效的工作流版本；默认选推荐版本但允许人工切换。报价保存 `workflow_id`，接受报价时订单实例必须使用该值并留审计记录。

### D-02 订单详情不能就地新增司机和车辆

- 严重度：P1
- 现状：运输安排只能选择承运商已有资源。
- 影响：临时司机、临时车辆或首次合作资源必须离开订单另行建档，业务在订单页面中断。
- 建议：司机和车辆下拉增加“新增”入口，弹窗完成最小资料登记；保存后自动选中，同时写入承运商资源库和操作日志。

### D-03 同一客户可出现多个主联系人

- 严重度：P1
- 现状：新增刘雨晴并设为主联系人后，周启明和刘雨晴的 `is_primary` 同时为 1。
- 影响：报价自动继承联系人不确定，本轮实际带出了旧联系人及其错误电话。
- 建议：以事务保证同一客户最多一个主联系人；设置新主联系人时自动取消旧主联系人，并增加数据库唯一约束或等效服务端校验。

### D-04 手机号未拦截字母 O

- 严重度：P2
- 现状：`13873O82631` 可保存。
- 影响：短信、电话通知和客户联络数据不可用，并会被下游报价继承。
- 建议：前端即时提示并在服务端执行同一规则；保存前规范化空格、短横线，拒绝非允许字符。

### D-05 中国地理主数据缺少湖南省、长沙市

- 严重度：P2（环境/主数据）
- 现状：中国下只发现新疆、广东，无法直接完成湖南长沙报价。
- 影响：业务无法覆盖未预置地区，即使页面支持临时详细地址也无法选择省市。
- 建议：补齐中国省市基础数据并提供主数据维护机制。临时详细地址可以不进入客户地址簿，但国家、省、市仍应来自完整基础数据。

### D-06 普通客户地址缺少统一的省市层级

- 严重度：P3
- 现状：普通地址表单使用国家加自由文本城市，与提货地址和报价三级地址模型不一致。
- 影响：客户主数据可能产生“广东省东莞市”文本与标准地区编码并存，降低筛选、统计和自动带出质量。
- 建议：客户地址统一复用国家—省/州—城市级联组件，并保留独立详细地址文本。

## 6. 业务逻辑评估

1. 临时地址策略合理：省市采用标准主数据，详细地址可仅存于报价和订单，避免一次性地址污染客户常用地址簿。
2. 工作流字段策略采用实例快照是合理的；实测模板变化可以同步到已存在订单，满足“执行中调整后续门禁”的要求。
3. 已使用流程冻结节点结构、允许调整字段策略，符合避免运行中节点拓扑突变的原则。
4. 未使用流程能够增加节点、字段并发布，底层实例生成也能识别新节点；但缺少报价选版入口使配置能力与业务入口脱节。
5. 司机、车辆属于可能临时出现的执行资源，完全依赖预建主数据会中断订单办理；适合采用订单内快速建档、后台补充完整资料的模式。

## 8. 建议修复顺序与复测重点

1. 先补报价工作流选择、订单工作流可见性及切换入口，再复测新节点的正常 UI 投产链路。
2. 修复主联系人唯一性，清理本测试客户的双主联系人，再验证报价默认联系人。
3. 增加订单内司机、车辆快速建档并复测当前订单运输安排。
4. 增加手机号前后端一致校验，并补 `0/O`、`1/I`、空格、短横线、长度和空值用例。
5. 补齐地理主数据并统一客户地址模型。
6. 在上述入口完成后，把测试订单真实推进到新增节点，补做“未填必填字段阻断—填写后解除”的最终黑盒验收。
