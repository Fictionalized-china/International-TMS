# 真实业务全流程测试用例（企业创建至动态工作流门禁）

## 1. 测试目标

本轮测试以一笔独立的拼车业务为主线，从企业客户建档开始，依次验证联系人、常用地址、临时提货地址、询价报价、报价接受、订单生成、运输资源登记，以及订单执行期间动态调整工作流字段和新增工作流节点后的实际效果。

本轮不做压力测试。测试重点是页面可操作性、业务数据继承、工作流版本选择、后续门禁同步和模块之间的衔接。

## 7. 通过标准

1. 企业、联系人和地址能够按真实操作顺序完整建档。
2. 未登记的长沙提货地址可直接用于单次报价和订单，但不会未经确认写入客户常用地址簿。
3. 报价页可以明确选择兼容的已发布工作流版本，生成订单后版本关联一致。
4. 订单详情可以就地新增司机、车辆并立即用于当前运输安排。
5. 执行中订单能够实时接收字段“必填/选填”变更，页面必填状态和服务端门禁保持一致。
6. 未使用工作流可以插入新节点和字段；发布并绑定订单后，新节点真实参与执行和门禁。
7. 全程不出现白屏、404、未捕获异常、重复订单或孤立数据。

## 8. 结果记录约定

- `通过`：页面操作、持久化数据和后续业务效果均符合预期。
- `失败`：系统有入口但结果与预期不一致，或发生错误。
- `阻塞`：缺少必要入口，导致后续步骤无法以正常业务操作继续。
- `部分通过`：核心数据可保存，但存在继承、入口或联动缺失。
- 数据库查询只用于核对页面结果，不替代正常业务操作；若必须用数据库辅助构造状态，报告中必须单独标注。
