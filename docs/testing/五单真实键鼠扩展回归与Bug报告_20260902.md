## 三、新增覆盖

### 1. 客户自助注册与后台绑定

1. 管理端通过“新增客户”创建客户6，不直接开通门户。
2. 客户在注册页键入企业、联系人、邮箱、密码并勾选声明后提交。
3. 后台批准前用相同账密登录，页面明确显示“注册申请正在审核中”，不开放客户数据。
4. 管理端选择最终客户并点击“批准并绑定”。
5. 审核后账号能登录，左侧“当前客户”、顶部客户名和账户邮箱一致。

### 2. 同一浏览器三窗口隔离

- 三个页面使用同一 BrowserContext，而不是三个独立浏览器。
- 三个 URL 的 `portalContext` 均为不同 UUID。
- 客户4只能看到自己的订单；客户5只能看到自己的订单；新客户6显示暂无订单。
- 逐页点击“账户中心”、刷新后，客户名、登录邮箱和 `portalContext` 均保持不变。
- 客户5窗口单独退出后，客户4和客户6刷新仍保持登录；客户5重新登录后恢复自己身份。

### 3. 客户门户其他功能

- 在消息中心找到指定报价的“新报价待确认”通知，通过按钮标记已读。
- 在“我的订单”聚焦快速查找输入框，键入报价号并按 Enter，仅返回 1 行。
- 点击“查看唛头”，核对订单号、客户、货物、打印按钮，再通过“下载 SVG”下载。
- 返回报价页并刷新，已接受报价没有重复接受按钮，仍指向原 SO 订单。
- 从订单行点击“查看轨迹”，URL 保留订单号及当前 `portalContext`，页面显示目标订单。

## 四、确认 Bug

### `TMS-QT-20260902-001` 询价报价数据增长后页面因 D1 变量上限返回 500

| 项目 | 内容 |
| --- | --- |
| 严重度 | P0 / 阻断 |
| 状态 | 已确认，未修复 |
| 触发页面 | `/admin/quotations` |
| 实际结果 | 系统恢复页；`D1_ERROR: too many SQL variables at offset 377: SQLITE_ERROR`；浏览器记录 HTTP 500 |
| 预期结果 | 报价列表和新建报价在数据量增长后仍可用，不应将全部 ID 以单条超限 bind 发往 D1 |
| 影响 | 询价与报价核心页面整体不可用，无法继续创建整车/拼车报价 |

复现运行：`20260902-extended-r6-042701`。该运行先通过两张整车单，随后在进入询价报价创建拼车单1时出现 500，后续 5 个依赖案例按规则截断。

代码层原因已定位：

1. `admin.quotations.tsx` 最多读取 200 条报价，随后把所有 `quoteRows[].id` 传入工作流字段与字段值查询。
2. `quotation-workflow-fields.server.ts` 为每个 ID 生成一个 `?`，并一次性执行 `quotation_id IN (...)`。
3. 当列表 ID 数超过 D1 单条 SQL 变量上限时，loader 整体失败。

建议修复方向（本轮未执行）：对报价 ID 分批查询并合并结果，或改为数据库内子查询/JOIN；同时增加超过 D1 bind 阈值的路由 loader 回归测试。

## 五、用例稳定性修正（非系统 Bug）

| 现象 | 证据判定 | 用例修正 |
