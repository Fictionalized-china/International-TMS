## 5. 工作流配置与门禁一致性

门禁不以页面中的固定文案或开发者假设为准，而是以订单创建时冻结的工作流实例为准。本次对每个门禁同时验证了：

1. 页面只渲染当前实例启用的字段、模块和任务。
2. 必填项未完成时，UI 提示与服务端拒绝原因指向同一配置来源。
3. 可选项未完成时不虚假阻断业务流。
4. 工作流模板后续变更不会倒灌改写已创建订单的历史事实。

最终认证时的费用结算配置为：

- `customer_service_confirmation`（费用确认）：必办，四票全部完成。
- `receivable_expenses` / `payable_expenses`：启用但为可选字段，四票均已填写。
- `business_review` / `finance_review`：当前冻结配置为可选；未完成不得构成归档阻断。
- 对账、开票、现金流水和核销当前不是业务归档必办项。
- 账单和收款凭证已通过 UI 上传并审核，作为财务跟进证据保留。

因此四票订单最终状态是 `business_complete_unsettled`，页面显示“业务已归档 · 财务跟进中”。这是对当前工作流配置的如实表达，不是流程漏走，也不应误标为“全部结清”。

## 6. 防呆与负向门禁

已实际验证的高风险场景包括：

- 拼车子订单组 PZ 并重分配后，原操作员和原单证员不再出现可办理入口。
- 原负责人即使知道 PZ 和子订单 URL，深链也无法越权。
- 操作岗在报关工作区仅可读，不渲染申报/放行操作控件；只有当前单证负责人可办理。
- 国内仓与境外仓的差异确认按仓库类型隔离，不允许跨仓确认。
- 入库、装车、境外入库和自提均以 OUL 逐件扫码为事实门禁，数量不齐时不能跳步。
- PZ 页面中的挂载订单、货物信息和货物码通过右侧抽屉就地查看，无需跳回第一票订单。
- 复盘归档拆分为“生成/更新复盘草稿”和“勾选确认后最终归档”两步，避免误点单次动作导致不可逆归档。
- 费用签核和归档后会等待可见结果状态，避免 SPA 导航竞态造成“后端已成功、脚本误报失败”。

| 问题 | 影响 | 处置 | 提交 |
