# 入口合并实施与验收

日期：2026-10-05。仅本地开发；不代表线上已经更新。

## 已完成

| 一级入口 | 内部子页面 | 原功能是否保留 |
| --- | --- | --- |
| 工作台 | 我的待办、运营看板 | 原待办与管理概览均保留，按菜单授权独立显示 |
| 调度与运踪 | 总览、运单档案、在途车辆 | 调度、每日运踪、时效预警、运单、运输段与在途台账均保留 |
| 订单中心 | 订单台账、货物检索、直接录单 | 普通订单/配载视图、货物和录单继续用原模块 |
| 费用结算 | 待我审批、对账与收付款 | 独立签核以及原费用、对账、流水、发票、历史均保留 |
| 销售管理 | 线索与商机、报价辅助 | 报价、客户接受和历史保留，不再作为开单前置主入口 |

全权限情况下一级入口由 24 项归并为 19 项，通知、人事专项、文件中心、配载单跟踪、其他业务资料与系统配置均保留。客户门户与仓库端菜单不在本次调整范围。

统一了页签和页面标题，使用原有紧凑按钮行、换行与键盘焦点样式，没有另起一套 UI 风格。

## 权限、逻辑与跳转防护

1. `admin-workspace-navigation.ts` 为无副作用映射：父入口在本账号有权访问的子页面中选择目标，不合并业务权限。不能访问财务金额的审批人员直接进入待我审批。
2. 原 24 项菜单权限代码继续保留；旧角色无需重新配置。角色配置说明展示新挂载位置。关闭一个子功能菜单不关闭另一个获授权子功能。
3. 费用金额页面仍同时要求 `billing.view` 和 `billing.sensitive.view`；审批入口不自动增加财务读取权。审批菜单准入补齐实际 loader 所需的 `order.view`，避免只有签核权限时显示必然无法进入的链接。
4. 只有货物检索、运单档案或报价辅助权限时，也能看到对应父入口；不会强迫开通订单总账、运踪总览或销售线索权限。
5. 直接录单入口按独立 `order.intake.manage` 显示；关闭报价菜单不影响有权人员直接录单。报价页面移除重复录单按钮，旧 `entryMode=direct` 网址仍使用原表单及服务端职责、费用、客服、人事门禁，在订单中心上下文显示。
6. 录单页不再混入报价列表及客户确认统计；在同一路由切换报价/录单时同步弹窗状态，减少错误页面上下文。
7. 精确按路径段及录单参数确定父入口和页签；支持路由默认接受的大小写和尾部斜杠。`/admin/orders-other` 不会被当成订单中心，普通报价不会被当成录单。
8. 新侧栏与共享页签显式保留合法 `itmsTab`；切换板块不携带另一板块的 `page`、`tab` 或筛选条件，避免串页签与错误分页。
9. 原路由全部保留，无新增重定向链。未改变 action、表单提交目标、订单队列返回上下文、下载、审批或节点推进逻辑。
10. 修正费用审批页向无财务读取权限人员展示财务链接的问题；同时将费用页面导航状态 Hook 移到权限早退之前，避免角色权限变化时破坏 Hook 顺序。
11. 点击工作台时，老板/操作主管默认运营看板，普通岗位默认我的待办；子页不可访问时选择另一有权子页。原登录后仍进入个人待办，保留原登录跳转行为。

菜单可见开关只控制入口，不代替服务端读写权限；若需要禁止旧网址访问，应撤销对应业务权限，而不是只取消菜单勾选。没有借入口精简删除业务模块或历史数据。

## 验证结果

- `npm run test:win`：230 个测试文件、1,408 项全部通过；包括原审批顺序、配载门禁、热更新、客户唛头、仓库实收和财务并发/重复提交测试。
- 新增 21 项测试：12 项映射/权限测试（其中一项遍历 128 种授权组合）、6 项页签服务端渲染、3 项录单/报价上下文渲染。
- 最后标题与页签间距调整后，定向重跑 6 个文件、39 项全部通过。
- 类型检查通过；D1 构建、MySQL 兼容检查与 MySQL 构建通过。构建清理本地环境文件，没有上传构建产物。
- 本地 HTTP：12 个受保护入口均按预期 302 到登录；客户登录 200，管理与仓库登录的无标签网址先生成 `itmsTab`。
- 路由表、数据库迁移与业务 action 未修改；没有修改真实订单、没有推送 Git、没有部署云端。

## 未验证与边界

自动化及构建通过不等于“绝对无 bug”。本轮没有已登录各岗位的浏览器端到端视觉验收，也没有运行生产 MySQL 或线上子域名验证。页面展示依据服务端渲染及现有布局合同验证；不同屏幕尺寸、真实账号权限配置与交互手感仍需下述人工验收。

没有发现本批入口调整引入的已知业务逻辑或跳转回归。菜单合并不解决人为配置无人办理、缺失责任人或无效节点的业务问题，原配置校验和办理门禁继续保留。

## 人工验收标准

仅在本地 `http://127.0.0.1:5189` 验收，使用测试账号与测试订单，不修改真实订单。

1. **工作台**：普通岗位点击工作台进入我的待办；老板/操作主管进入运营看板。来回切换、刷新、前进后退，只有一个父入口高亮、一个子页面标为当前。
2. **订单中心**：只读账号没有录单入口；业务员能打开直接录单。录单页只呈现录单内容，关闭后能重新打开。整车费用必录与拼车提货、自送显式 0 的原门禁仍有效。
3. **货物检索**：从订单中心进入，货物明细及原关联订单链接正常；原货物网址仍可访问。仅货物授权账号不出现无权访问的订单台账页签。
4. **运踪与档案**：从调度与运踪切换运单档案、在途车辆；原运单和运输段操作可正常使用，预警与客户端可见轨迹不受影响。
5. **审批隔离**：操作/业务审批账号能从费用结算进入待我审批；无敏感财务权限时没有对账与收付款页签，直接访问财务旧网址也不加载金额。审批仍按岗位、个人责任和顺序门禁办理，不能越级。
6. **财务**：财务/出纳获原有授权后仍可进入对账、发票、收付款及历史；各页面原表单和冻结节点门禁保留。
7. **销售辅助**：报价只从销售管理的子页进入；关闭报价菜单不影响直接录单。原报价历史、客户接受与相关订单仍保留。
8. **菜单配置**：在测试角色中单独关闭任一个子页，其他已授权子页仍可进入；不因开启审批而获得财务金额权限。确认后恢复测试配置。
9. **多标签与返回**：两个不同岗位分别登录两个浏览器标签，切换子页后保持各自账号；从订单详情返回原订单筛选列表仍正常。
10. **视觉**：常用桌面尺寸和窄屏查看，页签可换行、不挤压内容；键盘 Tab 可聚焦；客户和仓库菜单没有被本批删改。
