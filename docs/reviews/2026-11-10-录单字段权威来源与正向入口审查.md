# 录单字段权威来源与正向入口审查

日期：2026-11-10。用途：B0/B2 实施索引，不是全部需求完成证明。仅本地开发，不推送、不发布、不改内网。

## 一、字段口径与唯一来源

报价是来源凭据；形成订单后，下游读取当前订单和所属模块事实。订单当前值为空时不能再用旧报价非空值掩盖缺项。原始 `transport_order_quote_snapshots` 保留来源，不随补录重写。

| 红字或文字要求 | 当前权威数据 | 录单入口/下游使用 | 本地落实情况 |
| --- | --- | --- | --- |
| 委托人 | `transport_orders.customer_id` → 客户档案 | 直接录单“客户与方案”；委托/费用/客户隔离 | 已有；仍查当前组织/客户权限 |
| 业务大类、业务类型 | 尚无可确认的一对独立业务字典 | 不能以整车/拼车、出口等概念重复顶替 | 待明确选项；已发非阻断问题，其他开发继续 |
| 业务性质 | `transport_orders.business_nature` | 委托已有出口/进口/过境/国内 | 保留原编码，不等同于业务大类 |
| 装车方式 | `transport_orders.business_type`（`ftl`/`ltl`）；来源 `quotations.road_load_type` | 录单整车/拼车；冻结流程、配载/整车执行 | 原类型不改义，不另建另一份装车事实 |
| 运输方式 | `transport_orders.transport_mode` | 当前直接录单为 ROAD；既有运输字典 | 不冒充独立业务分类 |
| 业务员 | `transport_orders.salesperson_user_id` | 客户与方案；订单归属、人事/查询范围 | 已有，不能由报价商务或录单人替代 |
| 报价商务 | 订单 ID + `quote_commercial_name_snapshot` | 客户与方案；委托/审批/后续人事 | B1 已录入继承、更正原因留痕；人事全委托台账未完成 |
| 业务助理、客服 | 订单 `intake_operations_json` 人员 ID + 姓名快照 | 运输计划；委托、主管分配预选 | B1 已录入；不等于自动完成主管分配；历史归属与实际可办理人分开 |
| 委托服务 | `order_services`；来源计划在 `intake_operations_json` | 运输计划勾选；决定模块/分支启用 | B1 创建/重接受继承；B2 校验以实际订单服务为准 |
| 头程/尾程承运计划 | 订单 `intake_operations_json.headCarrier/tailCarrier` | 运输计划；委托/审核 | B1 已做；尾程默认来自策略 `order.default_tail_carrier`，不算实际找车 |
| 头程/尾程车量 | 同 JSON `headVehicleCount/tailVehicleCount` | 运输计划；委托/审核 | 计划正整数 1–10000；B2 补拒绝持久化零/小数/字符串冒充 |
| 预计发车/到达 | 同 JSON `plannedDeparture/plannedArrival` | 运输计划；委托/审核 | UTC 保存、北京时间展示，到达不早于发车；不覆盖真实发生时间 |
| 起运地/目的地/航线国家 | 订单 `origin_*`、`destination_*` | 路线与货物；运输、仓库及运踪 | 录单已有；不要从计划地点推断实际到达 |
| 出境口岸 | 订单 `exit_port`，基础字典 `border_port` | 路线与货物；委托/配载/找车 | B1 前移并继承；B2 不再回退读取旧报价 |
| 中转地/清关地 | 订单 `transit_locations/customs_location`，对应字典 | 路线与货物；委托/配载 | B1 前移并继承；旧值不因字典之后停用自动清空 |
| 国内代理 | 订单 `domestic_agent` | 路线与货物；委托/审核 | B1 已做；与 RO 无关，RO 不改 |
| 中文品名 | 每行 `order_cargo_items.cargo_name_cn` | 录单数量与尺寸/已有货物维护；仓库/单证 | B2 存在性逐行，不只看源报价或汇总 |
| 商品件数/单位 | 每行 `declared_quantity/declared_unit` | 货物；商业/报关/标签内容 | 与物理包装数分开，不用件数驱动扫码 |
| 入仓包装数 | `order_cargo_items.package_count` + `order_cargo_packages` | 数量与尺寸；唛头/收货扫描 | 用现有包裹身份、顺序和累计，不造第二份库存 |
| 毛重 | 每行 `gross_weight_per_package_kg`，订单汇总由货物编辑器维护 | 货物；委托、仓库对照 | 校验每行；实际称重仍属仓库事实 |
| 体积 | 每行 `volume_per_package_cbm`，订单汇总同源 | 货物；委托 | 明确 0/极小值合法；收货不恢复体积必核对 |
| 客户应收 | `business_expenses` 有效 receivable 行 | 客户应收；订单费用台账、结算 | B2 校验读本单，不用旧 `quotation_charges` 顶替；明确零有效 |
| 开单应付 | 同表 payable 行；类别要求来自业务策略 | 开单应付；操作维护、审批、结算 | 已修同名应收不能顶替应付；所有推进口的完整单行/事务门禁未完成 |

`order-intake-facts.ts` 负责订单到原生字段的同源投影；`quotation-native-field-catalog.ts` 与 `intake-operations.ts` 负责字段目录及合法值存在性。它们不是新业务存储，不建立第二份费用或库存。

## 三、阻断前必须存在的补录路径

1. 旧草稿与在办单都有明确缺项及补录责任人；业务、操作、老板按当前授权补录，不让仓库/出纳通过假数据解锁。
2. B2-C 已增加当前订单内计划、线路、报价归属的“只补缺项”入口（订单关键资料 → 资料补录），现有有效值只读；服务/货物/金额的补录与关键更正仍需各自模块及完整校验衔接。在所有必要补录路径闭环前，不批量给旧单加新硬锁。
3. 普通补录保存可保留其余缺项；只有向前办理检查完整集合。已审关键资料/金额的更正要留原因、版本和对应重审，不回退无关库存/运输。
4. 已取消/完成/归档单不自动重开；历史不足可见。受控重开走原授权后再适用明确规则版本。
5. 这轮 B2 的同源存在性修复不等于所有红字约束已经绑定全部订单；激活版本与旧单补录仍需单独完成/验收。

## 五、B2-D1 与 B3 衔接补充
