# 委托审核、人事台账与只读运踪联合验收

日期：2026-11-16。范围：B3-B、B4-A、B5-A 的本地联合批次。按用户“集中修改后统一回归”的要求安排；必要定向检查用于定位问题，完整回归只针对最后一致的代码版本运行。当前不推送 Git、不部署云端、不调整内网。

## 本批改动

### 委托审核与本单钱款

- 审核分配默认展开当前委托资料、逐条货物和应收应付；只读参与人也能看已授权的资料，不再只有审批状态表。
- 费用直接读取本单 `business_expenses`，包括来源报价继承、开单应付和后续新增费用；来源报价保留为独立历史参考，不与当前台账重复计入合计。
- 原币分币种显示，折算金额明确标为 CNY。取消费用仍保留记录但不计合计；零费用不等于缺失，异常金额/汇率不冒充合法差额。预计收支差额与真实收款、正式毛利分开。
- 订单可见范围不变。本单业务员、具备费用维护能力的实际责任人可读必要业务金额；不因此授予银行资料、跨单账本、资金登记、核销或运踪修改权限。利润和完整财务字段仍走既有独立权限。
- 直接请求审核服务也不能盲审：当前责任人失去费用读取能力后拒绝审核通过，提交事务再次核对相应权限。驳回仍可用，不把补录纠错一起锁死。

### 人事全委托台账

- 人事页分“全部委托与报价归属”和“已回款提成依据”。原已回款报表、人工提成登记、历史、周月快照和既有可登记条件保留，不自定提成比例。
- 全委托视图含未回款、草稿和历史订单，按组织与现有订单范围读取。日期、报价商务、业务员、整车/拼车（装车方式）、应收/应付核销状态可筛选并同口径导出。
- 报价商务使用订单人员标识和姓名快照，不猜成业务员或录单人；历史空值明确标识。筛选同名不同人按身份区分，同一人的新旧姓名优先采用最近记录。
- 预计/确认应收应付、有效收付款核销、已确认配载分摊分列。分摊已经进入应付，不再二次累加。登记流水但没有分配核销，不算已回款。
- 金额查看、报表查看、导出分别授权；没有金额权限时响应和 CSV 都不返回金额，不通过界面隐藏掩盖接口泄露。沿用现有 CSV 公式注入防护。

### 各岗位只读运踪

- 管理端：订单中心 → 订单运踪（只读）；具体订单右侧亦有入口。没有开通调度工作台也可按原订单范围查看，不给登记权。
- 仓库端：订单运踪（只读）。以当前绑定仓库的实际/计划业务关系限制，不能通过改 `warehouseId`、订单 ID 或旧计划目的仓查看无关订单。
- 运踪按现有 `shipment_events` 读取；日常及整批运踪继续由现有业务服务写入，不新增第二套轨迹。订单与事件独立分页、空态、查询中状态和北京时间显示。
- 查看历史运踪不初始化或推进库存/工作流，不要求历史订单先存在可发布的新模板；页面没有 POST 办理入口。
- 一并限制原仓库公共布局的上下文查询，避免用同组织任意订单 ID 在标题栏获得无关订单信息。

### 真实请求和视觉检查抓到的问题

1. 首次真实 HTTP 导出失败，原因是有 React 页面的 loader 返回 CSV 后仍进入页面渲染，`loaderData` 被当作报表对象读取。这是正常下载链路错误，函数测试单独拿到 Response 不足以证明可下载。已增加独立资源下载路由 `/admin/hr-reports/export`，旧链接转入该路由；新旧回款/全委托导出沿用各自查询与权限，并保留会话槽和导出审计。
2. 发现该错误时已主动终止当时的完整回归（`work/business-b3-b5-full-20261116.log`，未完成，绝不计为通过），修好后再对最后版本统一执行。后续结果见最终续记。
3. 浏览器复现中等宽度的审核区被资料表格撑宽。已限制父级网格最小宽度，并将审核里的同源资料改为四/二/一列分组展示；不改别的办理页字段、编辑方式或配置。费用表保留真正的横向滚动，不隐藏金额。预约/货好时间明确按北京时间展示，不再显示 ISO 原始串。
4. 实际查看人事截图发现页签没有使用现有按钮样式、装车方式选择框窄于其他字段；已沿用现有蓝橙页签样式、统一筛选控件宽度。同名人员筛选保留不同 ID，不混算。
5. 顺手收紧来源报价费用查询的组织限制；破损历史订单若误连另一组织的报价，也不能读取其费用。独立跨组织夹具通过；没有改写或修补任何实际来源报价。
