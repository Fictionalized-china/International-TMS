# 分步录单与多行费用修复

## 本批结果

已完成本地开发、回归与浏览器验证；未推送 Git、未部署云端，未推进或修改任何现有订单。

所属模块为订单中心直接录单，沿用报价转订单的共用创建能力、权限、费用台账、审计和防重复提交，不增加新的业务审批节点。

## 原因与修改

- 原弹窗将客户、路线、货物、应收与六类应付全部堆在一页。改为五步导航，底部固定上一步、下一步和最终确认；只显示当前步骤，已经填写的其他步骤保持挂载，不禁用或遗漏提交值。
- 费用列表每页五条，新增费用会自动进入对应页。每条提供“＋ 同类”和删除，支持同类多个数量、单价与独立备注；应付每条有独立往来单位。补充打包费类别，使用系统逐行计算和合计，不要求人工先汇总金额。
- 原开单应付只有每类金额和一个共享往来单位，创建订单时强制数量 1；同类费用还共享唯一 source_id。现在保存真实数量、单价、金额、往来单位、备注，每条拥有独立来源标识。无需迁移数据库，不改写历史费用。
- 服务端重新计算金额，不信任提交的小计；空白不是 0，明确免费仍允许单价 0。限制单次每个方向最多 100 条，拒绝无效、部分填写、超限和不完整数组，保留旧表单与旧重试记录兼容。
- 保持整车六类 / 拼车提货费、应收应付方向、自定义费用配置与权限门禁。后续订单费用原有“新增费用”及数量单价输入已存在，未扩大单证、运踪岗位对业务费用的权限。
- 跨步骤校验会打开错误步骤及费用页，Enter 不能提前创建订单。下一步和最终确认使用不同按钮标识，防止按钮从 button 切成 submit 时意外提交。
- 直接录单改为挂载后打开弹窗，避免服务端未输出 portal、客户端首次却已输出 portal 的 hydration mismatch。普通报价辅助保持单页，不改变其审批与通知路径。

小屏幕或大量配置字段保留局部滚动，固定底栏始终可达；不是通过缩小文字或裁切必填项来假装一屏展示。

## 拼车流程 HTML

桌面文件：`International-TMS-拼车业务流程与岗位入口.html`。

离线单文件，无外部库；19 个节点、15 类岗位视图、连接线与点击详情。说明账号登录落点、菜单 / 页签 / 行按钮、办理动作和下一岗位。应收 / 应付按独立并行链展示；岗位视图只突出本人动作。账号是本地登记信息，不提供密码或承诺云端注册状态相同。

HTML 不属于系统业务页面，未更改菜单。操作主管、出纳、单证账号视图与节点点击已在浏览器验证。
