# 部署前代码复查

## 范围

本轮检查业务逻辑、字段权限、数据一致性、事务并发、仓库实收、费用签核、运踪与 MySQL 兼容性。按本次要求不扩展跳转审查，不单独修补任何现有订单。

## 已复现并修复

1. 商务找车资源在读取后被其他提交更新，原实现仍返回重复成功并可能留下虚假成功日志。增加同事务资源一致性门禁，冲突整体回滚并提示刷新，正常重复提交仍幂等。
2. 每日运踪把 ISO 时间和 MySQL 日期字符串直接比较，可能放过早于实际提货的在途轨迹。改为 UTC 时间值比较；无效历史时间明确阻断，不推进结构节点。
3. 云端 MySQL 8.0.36 的严格模式实测拒绝带尾部 Z 的 ISO 时间字符串写入 DATETIME；原生配载提交表、分析配置等日期列将导致保存失败。新增版本 180 迁移，只将列入白名单的功能表时间列统一为与 D1、既有 MySQL 主业务表一致的 ISO 文本契约；保留历史时间、空值和原字段可空性，不修改订单、货物、运单等主业务数据，也不改写已应用迁移的校验值。已在同一生产 MySQL 的连接私有临时表验证真实迁移，历史毫秒、空值、ISO 新写入均通过，临时表随连接结束自动释放。
4. 原生 MySQL 迁移遗漏本地 0163–0166 的 P0 岗位与流程升级：线上运踪岗仍停用、业务主管仍有效。新增版本 181 前向补齐标准及版本化流程的询价节点退役、独立运踪岗位、未完成审批责任迁移。不清空已有自定义权限，不改写已完成责任历史，不针对单个订单修补。
5. MySQL `GROUP_CONCAT` 的默认截断可能丢失聚合出的岗位权限和多订单摘要。每个运行连接设置 65,535 字节上限，避免正常岗位权限集被静默截断；补充连接初始化回归契约。
