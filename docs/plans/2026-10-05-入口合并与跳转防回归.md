# 入口合并与跳转防回归

## 目标与约束

实施已确认的五项入口合并：工作台、运单档案、待我审批、货物检索、销售辅助报价。仅本地开发，不推送、不部署、不修改真实订单。

菜单合并不等于授权合并：保留原来的 24 项菜单权限及业务读写权限，展示层归并为最多 19 个一级入口。子页独立授权，父入口选择本账号实际可进入的子页；财务金额仍需原有双重读取权限。

## 当前结构与决策

- 原菜单与角色勾选来自 `app/lib/admin-navigation.ts`，后台布局手写了 24 个入口。
- 原路由具有独立 loader/action 和权限校验，全部保留，不通过跳转替换 POST、下载、审批或节点办理。
- 新增无副作用的入口/页签映射，供侧栏及各子页共用。旧深链接仍有效，直接录单旧网址在订单中心上下文展示。
- 工作台保留我的待办和运营看板；管理岗位默认看板，普通岗位默认待办，缺少子页授权时自动选择另一个可访问子页。
- 运单和在途车辆归属调度与运踪；货物检索归属订单中心；独立签核归属费用结算；报价归属销售管理。
- 订单中心的录单按钮按录单权限显示。报价页不再提供另一个录单按钮；录单表单仍复用原模块及服务端门禁。
- 角色配置继续使用原菜单开关，文案说明各子功能现在的挂载位置，不引入硬编码全模块写权限。

## 边界

不重写订单流程、财务链、数据库结构、热更新策略、客户门户或仓库菜单。权限不足时不显示可点击但必然被拒绝的父入口。共享导航只携带合法的 `itmsTab`，不将不相干的筛选参数串到另一模块。

## 实施顺序

1. 补权限组合、父入口默认目标、精确路径匹配和旧网址归属回归测试。
2. 实现统一映射及页签，替换后台侧栏，将五组子页面接入。
3. 修复未授权录单按钮和财务页面误导链接，更新配置说明。
4. 定向测试、全量测试、类型检查、D1/MySQL 构建及本地 HTTP 检查。
5. 保存验证报告和人工验收清单，创建仅本地 Git 提交。

## 验收

- 全权限账号最多 19 个一级入口；24 项历史菜单权限无丢失、无隐式授权。
- 审批但无财务敏感读取权限的账号能进入待我审批，不能加载金额页。
- 只有货物/运单/报价子功能权限的账号仍有可用父入口，不要求新增其他子功能权限。
- 订单、配载、文件、费用办理动作沿用原路由；旧链接、刷新、前进后退保持正确归属。
- 直接录单只有订单中心入口；只读账号没有录单按钮，报价停用不影响有权人员录单。
- 正常、缺权限、仅单子页、菜单开关关闭、管理/普通岗位默认入口、相似错误路径、多标签会话均有自动回归。
