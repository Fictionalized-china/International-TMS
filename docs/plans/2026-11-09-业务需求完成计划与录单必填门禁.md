需求依据：[11 月 5 日需求稿](2026-11-05-开单审批与仓库图片需求确认稿.md)、[当前未完成清单](../reviews/2026-11-09-上次业务需求未完成清单.md)及用户本次补充：“原本表单中红字部分是录单时必须录入的”“红字部分不补齐不允许进入下一节点”。本计划补充并优先明确上述门禁；不将性能优化阶段当作业务需求完成情况。

## 一、交付目标与已确定边界

1. 下单前已知资料在录单一次填写；后续委托、审核分配、仓库、运输、费用、人事均引用同一份数据。
2. 原表单红字及红色星号字段全部纳入录单必填。录单确认、提交审批及后续向前流转均由服务端检查资料完整性，不能通过另一入口跳过。
3. 报价商务独立留痕；业务员、实际录单人、后续找车经办人不相互替代。人事据同源资料导出并计算提成。
4. 主管审核时完整默认展开本单资料与应收应付；业务、操作、客服能够看到职责所需的金额，操作按职责维护费用。
5. 所有内部岗位可查看其授权范围内的运踪；现场图片持久保存并自动同步所属客户。
6. 保留老板单人办理、各岗位协作两种模式，老板有代办权限但不豁免资料、费用、库存和资金门禁。
7. 保留当前蓝橙视觉风格、页面功能、审核分配同页办理、模块配置与热插拔。不恢复询价报价节点或业务主管审批。
8. RO 代理不改；截图其他非红字段不额外增加必填。此前文字明确的报价商务、起运地、国内代理和费用要求仍在范围内。
9. 新的配载分摊人工输入/算法方案继续暂缓；已发现的现有负尾差缺陷作为独立修复项处理，不借机更换业务算法。提成比例未确定，不实现自动计算提成。
10. 本地开发与隔离验收完成后供用户检查；云端发布仍需后续明确指令。当前暂不做内网连接调整。

## 二、录单必填字段范围

### 2.1 原表单红字字段

| 分组 | 录单必填内容 | 口径 |
| --- | --- | --- |
| 委托信息 | 委托人、业务大类、业务类型、委托服务 | 使用清楚区分的业务字典；委托服务至少选择一项适用服务 |
| 运输计划 | 头程承运人、尾程承运人、装车方式、头程车量、尾程车量、预计发车、预计到达 | 头程必填；尾程默认“口岸调度”；车量是计划数量，不要求提前填写全部实际车牌和司机 |
| 线路清关 | 口岸、目的地、中转地、航线/国家、清关地 | 录单即明确，后续自动继承；起运地另按用户文字要求必填 |
| 货物 | 中文品名、件数、毛重、体积 | 逐条货物校验；商品件数与预计入仓包数分开；汇总自动计算 |
| 责任人员 | 业务员、业务助理、客服 | 明确人员归属；岗位可选范围、兼任规则由配置控制，不新增审批岗位 |

另行纳入录单必填：**报价商务、起运地、国内代理、相应业务类型的应收应付明细**。

### 2.2 不能误判为缺失的值

- 体积必须明确录入或计算，但 `0`、`0.0000001` 都不因数值小而拒绝；空白与明确的零分开。不得把零体积回退成必填错误，也不得恢复收货体积必须核对的旧门禁。
- 客户自送时提货费明确登记为 `0` 可满足“已录入”；缺费用行、空金额、非法数字不等于零。
- 尾程默认“口岸调度”可满足开单计划值要求，但不等于实际运输资源已落实；后续配载找车与车辆绑定继续执行。
- 不适用必须是配置允许的明确业务选项，并保存适用原因；不得批量填写“无”、假人员、假车牌来绕过必填。
- 选择人员或主数据时核对组织、合法性及可选范围。合法历史记录不能仅因之后人员停用、承运商改名就被清空或永久阻断；历史归属与下一步实际办理人分开处理。
- 计划时间沿用系统现有统一时间口径并明确显示，保存统一时间值；预计到达不得早于预计发车。不得把计划到达作为实际到达事实。

### 2.3 开单费用要求

| 业务类型 | 进入审核分配前必须具备 |
| --- | --- |
| 拼车 | 客户应收明细完整；国内提货费的**应付**明细存在且完整 |
| 整车 | 客户应收完整；适用的全部开单应付费用完整。至少按现有策略核对提货费、装卸费、仓储费、报关/口岸费、境外司机费、转关费 |

保留同类多条费用、数量×单价、币种汇率、往来单位、备注和自动合计。费用分类与应收/应付方向同时校验，不能用同名应收代替必填应付；适用性与必录类别保持可配置。

## 三、“未补齐不得进入下一节点”的具体规则

### 3.1 保存与流转的区别

| 动作 | 红字缺失时的预期结果 |
| --- | --- |
| 保存未完成草稿 | 允许保留已填资料，明确显示“草稿／缺 X 项”，不派发下一节点任务，不视作提交成功 |
| 确认录单、提交审批 | 拒绝向下一节点提交；列出全部缺失项，保留已填内容并可定位字段 |
| 审核通过、确认分配、下一节点 | 重新检查同一必填规则及当前业务条件；缺项不得推进 |
| 批量办理、配载共同推进、任务完成、自动流转 | 覆盖涉及的每张订单；逐单报告缺项，不因换入口或自动处理漏检 |
| 直接请求接口、旧窗口提交、老板代办 | 服务端采用同样规则，不能靠移除页面必填属性或伪造参数绕过 |
| 查看、补录、保存更正、驳回/撤回及依法有权的取消 | 不因资料尚未补齐而失去相应入口；仍检查该动作原有权限和状态，不把纠错入口一起锁死 |

“下一节点”指业务状态向前推进，不是录单向导里的下一页；填写人员可以切换表单分区检查、补充资料，不因另一页尚未填写被困在当前页。

本次按“可暂存草稿，不能把不完整草稿作为完成录单推进”安排实现，避免校验失败丢失录入内容。现有确认录单功能不能暗中改为缺项也能成功提交。

### 3.2 同一规则贯穿页面与服务端

- 使用同一份字段注册表生成红字标识、完整性状态、录单校验、委托缺项清单与流转门禁；不得每页维护一套字段名单。
- 内置字段读所属业务表，自定义字段继续使用现有工作流值表；不在订单中心复制一套业务事实。
- 页面返回稳定字段标识、中文名称、缺失/非法原因、补录入口及所需岗位；例如“缺少：口岸、报价商务、头程车量”。不得只显示 `exit_port` 或“资料不齐”。
- 提交时重新读取当前权限、资料与配置版本。针对“审核时别人把字段清空”的竞争，门禁判断与状态提交要有事务或版本条件保障，不能只在 loader 中检查。
- 已审批资料的关键变更按现有受控更正与重审机制处理，审批不能继续引用已经变更的旧数据；不清除不相关的仓库、运输事实。
- 批量动作先检查所有目标。涉及共同状态的整批操作在任何一单不满足时整体拒绝，不能写到一半才报缺项；保持原有库存、账务原子性及幂等规则。
- 自动同步必须显示被阻断的原因，不能在用户打开页面时自动越过门禁，也不能因某单缺项使整个列表加载失败。实际业务事实不能丢失或被倒改来配合状态显示。

### 3.3 可配置性及防死锁

- 默认发布的拼车、整车配置中，本计划红字字段均为录单必填；字段顺序、分组、选项、默认值、适用类型和编辑岗位继续可配置。
- 配置发布时禁止“必填却隐藏”“必填但办理前任何人都不能编辑”“字段只挂在下一节点”“必需字段被禁用模块吞掉”等组合。
- 不把现有 `legacyRequiredWorkflowFieldKeys` 全表当作此次红字清单：它还包含实际出境、实收、单证等后续事实，提前必填会造成死锁。
- 沿用已发布版本与订单冻结机制；热更新只更新它原本负责的范围。修改新必填策略要生成可追溯的规则版本，不能静默篡改所有冻结流程。
- 对在办旧订单，启用前先生成缺项和补录权限清单，受控绑定新录单完整性要求；之后下一次向前办理同样受门禁约束。仅升级该要求，不强制替换整套历史流程，不回退已完成事实。
- 在办订单补录由有权限的业务/操作等责任人办理，老板可代办；当前仓库或出纳无编辑权时，能够看到缺项和责任人、发出补录待办，不能只留一个不可点击按钮。
- 已完成/取消/归档的历史订单保留真实状态，不自动重开；历史缺项显示为历史资料不足，不伪造报价商务或重写已结算金额。受控重开后的后续推进按适用的新规则校验。
- 补录完成后刷新门禁及相关待办，能够正常续办；不以跨请求缓存保存“曾经完整”结论。

- [ ] 新字段接入保存、读取、编辑、克隆/来源带入及报价转订单；源报价没有的数据需在录单补齐。
- [ ] 保存报价商务人员标识与姓名快照，更正有原因和历史；与业务员、录单人分别展示。
- [ ] 业务助理、客服等前置归属带入后续任务分配；仍需主管确认的任务保留，不要求重录已明确的人。
- [x] 增加明确的草稿暂存及继续录入；确认录单沿用幂等身份，不重复建单、费用、货物或唛头。（B1-E 本地验收，个人文字草稿/版本/重试及真实浏览器；附件重选限制见执行记录。）
- [ ] 录单分区保持紧凑对齐，缺项提示可定位，切页/失败不丢输入；不做全站改版。

**完成标准：**老板或业务代录都能准确保存报价人；重开草稿、刷新、进入委托和后续模块后，已填写信息完整一致，不重复填写。

### B2：红字硬门禁与费用门禁

- [ ] 实现公共录单完整性校验，并接入确认录单、提交、审批通过、分配及其他正向推进入口。
- [ ] 批量和自动流转采用相同要求；提交读取最新数据，并完成并发版本/事务保护，不能只依赖页面结果。
- [ ] 校验费用类别与方向、单行必要信息、明确零值，修复同名应收顶替应付的潜在路径。
- [ ] 同步缺项提示、责任人和补录入口；服务端拒绝时不残留半成功的状态、任务、资金或库存写入。
- [ ] 增加配置发布冲突检查及在办旧订单门禁适配；补录后正常恢复，不自动重开历史归档单。

**完成标准：**逐一删除任意红字项，老板和普通账号从任何正向入口均不能推进；补齐即可继续。合法的零体积、零提货费、尾程默认值可通过对应校验。取消/驳回/补录不被缺项锁死。

### B3：完整委托、审核分配与费用职责

- [ ] 委托单统一展现基本资料、线路、计划与实际、货物、责任人、应收应付、附件与修改历史。
- [ ] 明确区分已填、必填缺失、选填未填、合法不适用；表头、金额、单位与按钮对齐。
- [ ] 操作主管进入审核默认展开全部审批必要信息及双方向费用，核对费用、毛利口径后同页继续分配或驳回。
- [ ] 业务、操作、客服在各自授权订单看见职责所需的同源完整资料与钱款；操作能维护应收应付，修改已审费用触发相应重核。
- [ ] 保留订单内账单审核、出纳流水、财务核销、最终复盘归档入口与真实余额约束。

## 六、必须保留的验收场景

| 场景 | 预期 |
| --- | --- |

## 八、人类员工的操作舒适度（用户追加）

- 同一份资料选择后自动带入，常用操作在当前订单内完成；能复用的数据不要求重新录入。
- 必填检查尽量一次列全，点击可定位；保存失败、断网和切换录单分区保留输入，不让员工来回试哪个按钮能点。
- 仅对确有撤销困难的动作保留必要确认；普通保存、翻页和补录不叠加无意义弹窗。
- 按钮文案说明业务结果，提交时有清楚进度与结果；禁止无限转圈、重复点击产生多笔记录、无原因的灰色按钮。

- 保持表单、日期、单位、表格和按钮对齐；使用足够宽的列表和可发现的分页/滚动，不造成窄小窗口或多层滚动。
