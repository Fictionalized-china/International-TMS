# 岗位权限与账户权限积木

本系统采用“部门 → 岗位 → 个人账号”三级组织结构。岗位决定默认角色和权限，派单与审核必须落到具体个人账号；同一岗位在不同地区使用相同的权限基线。

## 订单出现规则

1. 业务岗可全程查看本人创建、本人报价或本人负责客户的订单，但只有流程到达其获授权节点时才能办理。
2. 其他岗位只有在订单推进到本岗位负责的当前节点后，订单才出现在“运输订单”和“任务工作台”。
3. 当前节点尚未指定个人时，订单进入该岗位所有人员的“待认领池”；任一人员领取后，只向被派人员、业务负责人和具备全部订单范围的账号显示。
4. 直接输入订单详情、运单、节点办理或标签下载地址时，服务端仍执行同一范围校验，不能绕过列表限制。
5. 老板和所有者拥有全部订单范围且权限不可抽走；财务会计、出纳按默认职责具有全部订单摘要范围。

## 正式岗位权限基线

| 岗位 | 默认数据范围 | 默认权限积木 | 明确不授予 |
| --- | --- | --- | --- |
| 业务岗 | 本人客户、本人订单全程；当前岗位待认领/本人任务 | 客户维护、客户敏感资料、销售、询价报价、订单查看 | 其他业务员客户、财务利润、非本人节点办理 |
| 单证（操作岗） | 当前岗位待认领池、派给本人的订单 | 审核派单、国内运输、仓库协调、装车、文件、报关、境外仓、异常、复盘、运单管理 | 独立运踪更新、费用结算、利润统计 |
| 运踪岗 | 当前岗位待认领池、派给本人的订单 | 车辆/运单查看与管理、每日运踪更新 | 客户资料、费用利润、其他执行节点 |
| 客服岗 | 全部客户；当前岗位待认领池、派给本人的订单 | 客户敏感资料查看、委托与货物、应收应付费用、账单对账、收款与核销 | 全部订单浏览、利润汇总、权限管理 |
| 商务报价岗 | 无默认业务数据范围 | 无；仅保留岗位与薪资归类 | 所有系统操作权限 |
| 前端配载岗 | 无默认业务数据范围 | 无；仅保留岗位与薪资归类 | 所有系统操作权限 |
| 财务会计岗 | 全部订单摘要、全部财务数据 | 应收应付、费用审核、发票与对账、业务统计、利润、导出、审计 | 收付款与核销（由出纳负责） |
| 出纳岗 | 全部订单摘要、全部财务数据 | 收付款登记、核销、财务查看、导出 | 费用审批、利润分析、业务节点办理 |
| 人事行政岗 | 组织、账号、部门、岗位、角色与审计 | 账号开停、组织维护、权限积木配置、安全设置 | 客户敏感资料、订单、应收应付、利润 |

仓库端账号仍使用独立的“仓库作业账号”和“境外仓库作业账号”，用于仓库站点登录及仓库节点办理，不计入上述九个办公室岗位。

## 账户权限积木

角色权限页分为两层：

- 岗位角色权限：定义岗位默认拥有的权限，可零权限保存，适用于只做岗位/薪资归类的角色。
- 账户权限积木：每项权限可设为“继承角色”“额外允许”“明确拒绝”。明确拒绝优先于任意角色授权。

所有更改通过“确认应用”一次性写入并记录审计。老板/所有者角色和账号属于系统保护对象，不能编辑或抽走权限。

## 敏感数据边界

- 客户联系人、联系方式、详细地址、门户账号和合同受“查看客户敏感资料”控制。
- 客户范围分为“本人客户”和“全部客户”；业务岗创建的客户自动归属本人，不能借直接地址访问他人客户。
- 应收、应付、利润和回款数据必须同时具备费用页面权限与“查看敏感费用”。
- 收付款/核销与对账/发票分开授权；数据导出、利润汇总也各自独立。

## 历史岗位迁移

- `DOC`、`OVERSEAS`、`BOOKING` 迁移到“单证（操作岗）”。
- `SALES_ASSISTANT` 迁移到“业务岗”。
- `FINANCE` 迁移到“财务会计岗”。
- 有仓库站点授权的 `CONTAINER` / `OVERSEAS` 账号分别迁入国内或境外仓库作业岗；无仓库授权的 `CONTAINER` 才迁到“前端配载岗”。
- 原岗位和角色保留为历史停用记录，不能再分配；相关个人账号自动挂到新岗位角色。
