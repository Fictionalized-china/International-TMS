# 汽运一期差距清单

本文档基于交接版本代码、既有需求基准和旧系统参考结论整理。目的不是重构系统，而是在当前系统基础上补齐“订单创建 -> 审核分配 -> 国内执行与跟踪 -> 口岸换装与配载 -> 出境后对账 -> 收付款与结算 -> 数据与复盘”的一期闭环。

## 一、总体判断

交接版本已经具备汽运系统底座：

```text
客户、报价、订单、运单、基础账单
订单详情页模块化结构
订单模块实例、模块历史、订单待办
仓库端收货、分拣、出库、库存、异常
拼车配载工作台、配载批次、车辆、装载校验
基础费用表、应收账单、客户门户付款凭证/账单异议
用户、角色、权限、审计日志
```

但交接版本还不是可交付的一期汽运闭环。核心缺口是：已有模块各自能做一部分事，但还没有按汽运真实业务形成统一工作流、统一下一步动作、统一门禁、统一费用闭环。

## 二、差距等级

```text
已具备：已有可复用底座，后续只需小改或接入工作流。
半成品：已有表或页面，但业务语义、门禁、状态、字段不足。
缺失：一期闭环必须有，但交接版本基本没有。
待确认：业务规则还没有最终确认，开发上只能先做可配置或半自动。
```

## 四、P0 必须先补的闭环

P0 是一期演示和真实使用前必须补齐的内容。

### 1. 八阶段工作流与下一步动作

现状：系统已有订单状态、模块状态、订单待办，但订单详情仍是“四阶段业务办理”，没有完整映射到汽运一期八阶段。

目标：

```text
订单创建
审核分配
国内执行
口岸配载
出境运输
境外仓自提
对账结算
完成复盘
```

必须实现：

```text
统一 next_action 计算器
统一 blocker 计算器
订单详情、订单列表、运单列表、配载池、费用列表、首页待办使用同一句下一步动作
阻断按钮保持可见但禁用，并显示原因和修复入口
顶部阶段悬停展开当前模块、下一步动作、负责人、阻断原因、跳转入口
```

### 2. 订单创建字段与主数据约束

现状：订单创建已有较多字段，但出口口岸仍偏自由文本，仓库没有角色，境外目的仓没有结构化选择。

目标：

```text
提货地址、提货联系人、预约提货时间在订单创建填写
出口口岸必须从口岸主数据选择
境外目的仓必须从仓库主数据选择
境外目的仓下拉只显示角色为“境外目的仓”的启用仓库
配载集货仓库只显示“国内集货仓”或“口岸仓”
创建页提供添加口岸、添加仓库入口
```

### 3. 审核分配

现状：有工作流动作和模块负责人，但还没有明确固化“审核通过 -> 操作主管派单 -> 主操作员”这一条业务规则。

目标：

```text
未提交、主管未通过，不允许派单
系统自动生成“待操作主管派单”
主管必须手动选择主操作员
建议操作员只能作为提示，不能自动生效
第一期每个订单只有一个主操作员
主操作员可分派模块任务，但不能改订单主负责人
```

### 4. 仓库实收与差异确认

现状：仓库端已有入库、分拣、齐套复核、出库；但订单预录数据与实收数据的差异确认没有形成订单级门禁。

目标：

```text
实收数据不覆盖订单预录数据
实收件数、重量、方数、包装、入仓时间、收货人、照片、异常备注作为一期必填
实收与预录差异超过阈值时生成待办
仓库作业可继续
最终对账前必须处理差异
拼车配载、车辆容量校验、成本分摊统一使用实收数据
```

### 5. 配载状态与出境确认

现状：配载批次已有 planning/loading/departed/arrived 等状态，订单在批次中有 planned/assigned/departed/arrived/removed，但与用户确认的业务状态不完全一致。

目标：

```text
待配载：货已实收，可进待配载池
已预排：临时放到某台车计划里，未确认
已配载待出境：已确认装车/车次，不允许再被其他车装载
出境运输中：已录出境时间/出境确认
已到境外仓：境外仓入库确认
待客户自提：已通知客户可提货
已完成自提：货物全部提走
```

必须明确：

```text
一票订单不可拆分到多台车
一票订单不可重复进入多个有效车次
确认配载前校验车辆容量
录入出境时间后才进入“出境运输中”
```

### 6. 境外仓自提

现状：交接版本没有完整的境外仓到仓、自提通知、客户提货模块。

目标：

```text
境外仓入库确认：实际到仓时间、境外目的仓、实到件数、包装状态
无差异后自动生成“待通知客户提货”
人工点击发送/复制微信通知后进入“待客户自提”
自提登记：提货时间、提货人、电话、提货件数、仓库经办人、签收/交接证明照片
全部提走进入“已完成自提”
少于总件数进入“部分提货/待继续自提”
```

### 7. 费用状态骨架

现状：已有费用表、stage、税率、业务锁、财务锁基础字段，但页面和流程没有达到旧系统费用闭环。

一期最小目标：

```text
预估应收 -> 确认应收 -> 客户对账/收款
预估应付 -> 确认应付 -> 应付对账/付款
应收、应付可分别完成、审核、锁定
业务锁、财务锁保留
锁定后不能改原费用，只能走调整/补录/红冲
确认后的费用才能进入对账、发票、收付款
```

订单详情顶部必须有费用预录状态卡和费用风险卡：

```text
应收未预录
应付未预录
应收未确认
应付未确认
预计利润为负
实际费用超过预估
费用未锁定
客户未回款但已付款申请
```

## 五、P1 建议补齐的结算与财务闭环

P1 是一期可用后继续打磨的内容，部分可先做基础版。

### 1. 客户应收对账

```text
同客户、同结算主体、同币种、已出境运输中的订单可合并对账
从订单详情可发起单票对账，也可加入已有待确认对账单
所有应收费用必须确认后才能进入客户对账
应付未完成不阻断客户应收对账，只显示内部风险
```

### 2. 应付对账

```text
按应付往来单位 + 币种合并
所选应付费用必须已确认
客户是否已付款不阻断应付对账，只显示风险
```

### 3. 发票记录

```text
应收费用生成客户销项开票记录
应付费用生成供应方进项收票记录
支持部分开票、部分收票
累计开票/收票金额不得超过费用金额
第一期不接税控系统
```

### 4. 收付款与核销

```text
收款/付款记录可先独立登记
后续再匹配到费用行
一笔收款可核销多条应收费用
一笔付款可核销多条应付费用
必须同往来单位、同币种
费用行与收付款记录都显示未核销余额
```

## 六、成本分摊半自动模块

成本分摊是当前最重要的未闭合业务规则之一。专业人员尚未最终回复，因此不能直接写死为不可变公式。

一期建议按半自动模块实现：

```text
系统生成建议分摊结果
操作或财务查看建议
人工允许修改分摊方式、比例、金额
修改必须填写原因
人工确认后才写入正式应付/成本
确认前只作为草稿，不进入对账、付款、利润正式口径
```

当前已知的临时规则：

```text
成本分摊只影响内部毛利，不影响客户应收
使用装车后整车实收数据，不使用订单创建预录数据
重抛比按 1:300 判断
整车 kg / cbm < 300 时按抛货逻辑
运费、装卸费、部分加固材料等按重抛占比分摊
转关费、报关费、入仓费等按票数均摊
```

例子：

```text
整车 23753 kg / 132 cbm = 179，小于 300，按抛货逻辑
运费 3000 USD * 每个订单占比 = 该订单分摊运费
报关费一车 10 票，总费用为 400 + 9 * 100，则每票均摊 (400 + 9 * 100) / 10
```

开发设计上需要留出以下字段：

```text
配载批次
车辆/车牌
整车实收总重量
整车实收总体积
重抛判断结果
订单实收重量
订单实收方数
订单占比
费用项目
费用总金额
建议分摊方式
建议分摊金额
人工调整金额
调整原因
确认人
确认时间
入账状态
```

确认后规则：

```text
生成正式应付成本费用行
参与利润统计
允许后续通过调整/补录/红冲修正
不允许静默覆盖历史分摊结果
```

## 七、未闭合关键点

以下问题仍然不能算已经百分之九十五确认，必须继续追问或通过旧系统/业务人员确认。

1. 成本分摊中“加固材料”到底按重抛占比分摊，还是按票数均摊，还是根据费用项目细分。
2. 重抛占比的精确定义：按重量占比、方数占比、计费重量占比，还是先算每票计费重量再按计费重量占比。
3. 1:300 的判断是只判断整车，还是也要判断每票订单。
4. 整车被判断为抛货后，每票是否全部按方数占比；整车被判断为重货后，每票是否全部按重量占比。
5. 成本分摊币种、汇率日期、汇率来源。
6. 人工调整分摊后是否需要财务审核，还是操作确认即可入账。
7. 成本分摊确认后发现装车数据修正，走红冲、补差还是重算生成新版本。
8. 境外仓自提是否需要客户签名以外的身份证/车牌信息作为强制项。
9. 境外仓超 7 天仓储费是否按自然日、工作日、还是从通知客户可提货后开始计。
10. 客户对账单与发票、收款的先后顺序是否存在客户差异。
11. 应付付款是否需要线上审批流，还是第一期只登记申请、付款、核销状态。
12. 老板/主管看板第一期最需要的三个指标：利润、未回款、异常、时效、人员工作量，优先顺序还未确认。

## 八、建议实施顺序

建议先做 P0，不先做复杂财务报表。

```text
第一批：主数据与订单创建门禁
第二批：八阶段工作流、统一下一步动作、阻断原因和修复入口
第三批：仓库实收差异、配载状态、出境确认
第四批：境外仓入库、自提通知、客户自提
第五批：费用预录状态卡、费用风险卡、应收/应付确认和锁定骨架
第六批：半自动成本分摊草稿、人工确认入账
第七批：对账单、发票、收付款、核销的完整财务闭环
第八批：订单复盘和老板/主管看板
```

## 九、当前结论

当前对目标系统的理解可以达到约 85%。主要流程、模块结构、岗位边界、订单不可拆分、仓库实收为准、人工决策优先、费用锁定原则已经清楚。

还不能宣称达到 95%，原因是成本分摊公式、费用审核权限、部分财务单据顺序仍未最终确认。开发上可以先按“系统建议、人工修改、人工确认后入账”的半自动方案推进，不会堵住一期主流程。
