# 费用签核入口与财务查看权限拆分发布记录

日期：2026-11-04。正式环境：https://tms.shxlh.com ，原阿里云 ECS。

## 复现与根因

订单 `SO2026110300027`（`6dc926e7-661f-498d-be88-82978afd65c6`）已经进入对账结算。本单操作岗在独立“待我审批”页可以复核应收和发起应付，但订单内嵌费用页显示“当前账号无需办理费用结算”。

原因是 `EmbeddedOrderModule` 在渲染任何费用内容之前，使用 `canViewExpenseSummary` 整页返回；把“看财务金额”误当成“办理个人签核”的前置条件。该条件会影响所有按配置参与签核、但没有财务明细查看权限的岗位，不仅是操作岗。

发布前使用增强后的生产只读脚本，实际复现了独立页有可办表单而订单页被财务查看门禁拦截的差异；不是依据 HTTP 200 推断功能正常。

## 修复范围

1. **拆分权限**：无财务查看权时，订单费用页展示不含金额的签核面板，不再整页拒绝。查看费用台账、毛利及结算文件的原权限仍保留；没有给操作岗新增敏感财务读取权。
2. **统一决策**：订单页和“费用结算 → 待我审批”共同使用 `loadMeetingSettlementDirections` / `meetingSettlementDirections` 和同一个签核组件。可办状态仍取自 `meetingSignatureAccess`，校验本单真实责任人、岗位配置、签核权限、冻结字段和前序必办动作。
3. **保持职责独立**：订单当前负责人、模块编辑权和财务读取权不再决定个人签核是否显示。实际出境后按配置已经开放的签核，不再额外被旧页面阶段门禁隐藏；业务提交仍由原签核服务重新验证，不绕过顺序、范围或历史只读规则。
4. **正确处理热拔插**：签核链全部隐藏时，保留原服务所支持的显式费用确认入口，避免只在独立页能确认、内嵌页无入口。没有把关闭的审批动作重新设成必办。
5. **减少点了才报错**：费用未录入或往来单位不完整时，两处页面都显示明确原因，而不是在内嵌页提供必然被服务器拒绝的提交按钮。
6. **修复旧入口跳转**：旧 `/modules/…` 地址跳回订单时，保留受支持的费用/文件子页选择和有效 `itmsTab` 登录标签标识，避免从“费用”落到“文件”或丢失标签账号。
7. **修正文案和状态**：可办个人签核时不再笼统提示整页“只读”；移除“客服、业务、财务三方全部并行”的过期表述，明确应收/应付各自独立、方向内部遵循本单配置。
8. **保持现有外观**：共用已有签核卡片、状态色、按钮与移动端单列规则，使独立审批页和订单页一致，没有更换系统配色、增加装饰或改动业务内容。

涉及的运行代码主要为：

## 人工验收重点

1. 操作岗进入“订单中心 → 本单 → 对账结算 → 费用”，应看到本人可办的应收复核、应付申请，不再被整页财务门禁拦住；与“费用结算 → 待我审批”一致。
2. 已完成的动作只显示完成状态，前序未完成的步骤显示应由谁先办理；操作不能代主管或财务审批。
3. 操作岗仍不能因此看到费用台账、毛利或银行账号，也不能进入未授权的财务工作台。
4. 主管、财务按各自前序完成后出现对应按钮；应收和应付不互相等待另一方向完结。
5. 从旧待办或模块链接进入，仍停留在正确子页和原登录标签账号。
