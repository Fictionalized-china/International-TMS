# 结算职责与零元费用修复发布记录

日期：2026-11-04。正式环境：https://tms.shxlh.com ，原阿里云 ECS。

## 问题与修复

本次针对订单 `SO2026110300027`（`6dc926e7-661f-498d-be88-82978afd65c6`）完成自提后，客服在结算页无法办理的问题。

1. **错误复用客户代录开关**：客户 `cs_order_entry_enabled=0`，旧签核判断将其用于禁止客服发起应收。现改为按应收发起岗位配置、签核权限、本单指定责任人判断；客户代录订单的限制保持不变，不扩大客服录单权限，也不允许其他订单的客服越权。
2. **审批人显示与后台不同**：页面从已经转交给操作岗的旧 assignment 模块取主管名字，后台却要求订单的操作主管。现由同一职责解析器决定可办人员和页面显示，使用直接主管、运输负责人、费用负责人、复盘财务等真实责任来源。
3. **拼车商务责任人遗漏**：旧代码只查整车找车请求。现可从有效 PZ 配载报价回溯商务办理人；保持操作/商务二选一发起应付，不要求重复申请。
4. **零元费用被当作未填**：费用单价的通用“正数才算已填”判断导致客户自送提货费 0 元阻断结算。现明确接受有效非负单价和零税率，区分空值、负数、非数字、无穷值；数量和汇率仍须有效正数，内部费用“否”也属于已填写。
5. **选办与必办判断不一致**：结算门禁现在与签核服务一致，遵守冻结工作流的必办/选办/隐藏配置；本单原有三项应收、三项应付必办签核没有删除。
6. **旧阻断摘要误导**：订单已进入结算，数据库中旧摘要仍写着“单价、尚未进入对账结算节点”。读取模块时按当前费用、签核及冻结流程投影最新摘要，不创建签核或改写费用；已完成的模块保留历史，不追溯重开。普通旧签核标签改为中性的费用确认/复核/审批，避免应收主管审批仍显示为财务动作；自定义标签保留。

岗位仍由流程策略配置，个人仍由订单分派决定。未知的自定义岗位只有被配置为签核岗位且确为该单已分派人员，才可办理；另需有效签核权限。顺序、订单数据范围、已结束只读、往来单位、事务及重复提交保护保留。

## 当前默认配置的正确步骤

客户完成自提意味着运输交付完成，不代表费用已审核、收付已核销或订单已归档。客服不应代替操作、主管和财务办理各自审批。

1. 客服岗账号（或本单业务员，二选一）：从订单对账结算页上方“出境后对账签核 / 付款审批”，或“费用结算 → 待我审批”，定位订单，办理“业务 / 客服发起应收”。客户自送的提货费用可明确填 0，不要虚增费用绕过门禁。
2. 操作岗账号：在相同签核页办理“操作复核应收”，并核对供应商费用后“发起应付申请”；若已由本单商务发起应付，不重复申请。
3. 操作主管账号：前序各自完成后，办理“操作主管审批应收”和“部门主管审批应付”。应收、应付两条链独立，不要求等另一方向完成才办理。
4. 财务会计岗账号：办理“财务审批应付”；若现有开关要求线下总经理审批，取得真实审批后登记审批人、日期和凭证，不添加业务主管节点。
5. 客服/财务：“费用结算 → 待对账”按各自职责从确认费用生成客户或供应商对账草稿，再到“对账单”复核确认；同一单不得混合不同往来单位、方向或币种。
6. 出纳：“费用结算 → 收付款核销”，按实际发生登记真实收/付款流水，匹配已确认对账单并核销；发票、凭证按配置及实际业务补充，不为演示虚构资金流水。
7. 财务：回订单“完成复盘”，保存复盘结果，系统按工作流核验结算、资料及结清状态，再进行最终确认/归档。
