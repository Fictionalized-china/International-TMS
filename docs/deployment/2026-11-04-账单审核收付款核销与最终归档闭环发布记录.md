# 账单审核、收付款核销与最终归档闭环

日期：2026-11-04。正式环境：[阿里云生产系统](https://tms.shxlh.com)。

## 需求与根因

本轮按项目负责人要求实现：各责任岗位核对账单并签核，生成、确认对账单，出纳登记真实收付款并核销，最后由财务复盘归档。审批人必须看到其审核方向的必要金额，但不因此获得毛利、银行资料或其他订单的读取权限。

原实现有三处断层：

1. 签核入口和敏感财务查看权限拆分后，部分审批人只能看到签核按钮，无法看到审核所需金额。
2. 冻结工作流的对账、流水、核销字段为可选时，原最终确认允许“业务先归档”；签核结束即可能完成业务归档，尚未真实收付款。
3. 已签核的历史任务缓存可使冻结结算模块提前变成完成；不能把这些任务当作资金结清证据。

另对齐了客户应收对账单生成岗位：后端、逐条费用选择控件、下一步链接使用相同策略判断，避免显示可选、提交却被拒绝。没有给财务越权生成未配置给它的客户应收账单。

## 实现范围

- 新增可配置策略 `settlement.approver_amounts_visible`，默认开启：本单真实签核责任人查看其参与方向的费用名称、往来单位、数量、单价、金额、币种和汇率；不包含毛利、银行信息等无关字段。
- 新增 `settlement.require_cash_before_archive`，默认开启：即使冻结模板将现金、核销字段设为可选，也必须以真实财务证据校验最终归档。关闭才采用原有业务先归档模式。
- 同一财务闭环判据用于模块门禁、最终归档预检与提交事务内的再次校验，覆盖同组织、同币种、同方向的已确认对账明细和未作废资金分配。
- 部分收款、未分配流水、作废流水、撤回对账单均不能视为结清；零金额或已取消费用不虚构资金办理。
- 冻结执行同步对尚未完成的最终必办结算模块采用同一规则，不因旧签核任务完成而提前标绿；已完成上游节点仍保留历史状态。
- 结算页与待我审批页保留现有配色、组件样式，并提供清晰的对账、出纳收付款核销、财务最终复盘入口。
- 提供明确确认、角色校验、组织隔离、事务保护及完整审计的历史订单恢复功能；只恢复财务节点，不自动签核或生成资金。
- 标准最终节点附带的已完成可选异常模块保持历史记录；自定义、未完成或必办的其他业务模块仍需核查，不自动回退。
- 原线下付款审批策略继续有效：需要该凭证时，由本单财务记录真实审批证据，不自动伪造。

没有增加数据库迁移、修改客户代录配置或扩大操作岗的敏感财务权限。

## 使用步骤与验收

1. 各责任岗进入“订单中心 → 本单 → 对账结算 → 费用”，或“费用结算 → 待我审批”，核对可见金额，按配置完成本人签核。应收、应付内部遵循各自顺序。
2. 客服在“费用结算 → 待对账费用”生成客户应收草稿；财务按应付方向生成供应商应付草稿。到“对账单”核对并确认。
3. 若付款策略要求线下审批凭证，本单财务在待我审批页记录真实审批人、日期与凭证。
4. 出纳进入“费用结算 → 收付款与核销”，实际发生资金后登记流水，再匹配同方向、同往来单位、同币种的已确认对账单，逐笔或分次核销。
5. 财务确认结清后进入“完成复盘”，更新最终结论、核对门禁，明确勾选确认后最终归档。收款未发生、尚未分配或仍有未结清应付时，应继续保留财务待办。
