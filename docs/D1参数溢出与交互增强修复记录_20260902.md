# D1 参数溢出与交互增强修复记录

日期：2026-09-02
范围：管理后台、客户门户、仓库端共用的数据访问与交互基础能力
验收边界：本记录只包含代码修复、自动化测试、生产构建和只读 HTTP 并发验证；未代替用户进行浏览器人工验收，未部署远端环境。

## 一、故障结论

截图中的报错不是页面按钮或浏览器卡死，而是报价列表加载时向 Cloudflare D1 提交了超过 SQLite 单条语句上限的绑定参数。

- 故障现场共有 100 条报价记录。
- 查询同时绑定 1 个组织 ID 和 100 个报价 ID，共 101 个参数。
- D1 单条 SQL 最多允许 100 个绑定参数，因此抛出 `D1_ERROR: too many SQL variables`，路由加载中断并进入系统错误页。
- 原报价页还会一次并发发起 11 个独立数据库查询，超过 D1 每次 Worker 调用可用的并发连接数量，数据量增加后还可能表现为等待、超时或偶发失败。

## 二、本次修复

### 2.1 直接故障

1. 报价工作流实例字段、报价工作流字段值改为：
   - 先去重报价 ID；
   - 每批最多使用 80 个动态参数；
   - 为组织 ID 等固定参数保留额度；
   - 分批查询后保持完整结果合并。
2. 新增统一的 D1 参数安全工具，集中约束：
   - 单语句最大绑定数为 100；
   - 动态 `IN (...)` 默认每批 80；
   - 多行插入按“每行绑定数”自动分块；
   - 空列表和超额占位符直接在代码层报出可读错误。
3. 报价页 11 路并发加载拆为 `4 + 4 + 3` 三波；报价字段和值随后以 2 路并发读取，单波不超过 4 个连接。

### 2.2 同类不可用风险扫描与修复

扫描范围包括动态 `IN` 参数、批量写入、`Promise.all` 数据库并发、订单/批次同步和三端高频加载器。已处理的主要区域如下：

- 工作流：模板字段、实例字段、必填校验、版本影响检查、执行快照同步。
- 订单：订单详情、订单模块、订单操作、订单复盘、办理提示、异常状态和费用结算。
- 配载与运输：批次轨迹、批次运输同步、装车详情、国内运输跟踪、境外仓到达。
- 仓库：仓库访问范围、仓库首页货物读取、库位批量创建、配载、装车出库、文件门禁和仓库进度同步。
- 门户与基础资料：客户门户首页、运费试算、角色权限、客户列表、销售工作台。

采用的处理原则：

- 有大量 ID 的查询统一分块，固定参数计入额度，禁止再次出现“100 个 ID 再加组织 ID”的 101 参数问题。
- 页面加载器中的 D1 查询按每波最多 4 个执行，给后续嵌套查询保留连接余量。
- 可表达为集合操作的逐订单写入改为单条集合 SQL，避免语句数量随订单数线性膨胀。
- 需要原子性的主业务写入仍保留在同一个 `DB.batch` 中，没有为了分块而拆散事务。
- 批次轨迹共享、订单模块轨迹同步均改为 JSON 参数展开的单条 `INSERT … SELECT`，消除“订单数 × 里程碑数”的语句扩张和跨分块部分成功。
- 海外仓到仓的主事务写入从 `2 + 6 × 订单数` 收敛为固定 8 条集合 SQL，仍由一个原子 `DB.batch` 提交。
- 海外仓到仓的运单事件与 `station_arrived` 里程碑增加幂等保护；已到仓/待自提状态可安全重试客户通知和流程快照，不会重复写轨迹。
- 主业务已落库、后置快照/审计同步失败时，不再谎报“整项操作失败”；页面明确提示哪一部分待重试，避免用户重复创建装车任务或重复确认出境。

## 三、交互增强（不改变业务逻辑）

本批只实施同页交互和全局基础反馈，没有改动业务节点、状态门禁、订单推进规则、页面跳转方向或三端职责。

### 3.1 防误操作与数据保护

- 创建报价、补充报价第一步字段、客户资料等高输入弹窗支持未保存检测。
- 修改内容后关闭弹窗、刷新页面或跳转路由会提示确认。
- 表单刚开始提交时短暂锁定弹窗关闭，避免瞬间误关与重复操作；超过 2 秒后允许关闭，并明确提示请求仍在后台处理，不会因长请求锁死用户。
- 弹窗标题区显示“未保存”状态。
- 危险确认弹窗默认聚焦“取消”，降低误按 Enter 执行删除、撤回等操作的概率。

### 3.2 输入效率

- 仅对明确标记的高频表单启用 Enter 连续录入。
- Enter 不接管文本域、下拉框、文件、复选框、单选框、组合框和中文输入法合成过程。
- 原有 `Ctrl + Enter` 明确提交能力保持不变。
- 快捷键帮助补充连续录入说明。

### 3.3 状态反馈

- 全局忙碌状态同时感知页面导航和后台 fetcher 请求。
- 连接状态不再用本地时间伪装成“数据已同步”，只表达“离线 / 正在同步 / 网络在线”。
- 报价创建失败会在当前创建弹窗内聚焦展示，已填写内容保留；其他报价操作的旧错误不会串入新建弹窗。
- 报价第一步字段配置、客户主档、合同、联系人、地址、提货点、门户账号和密码操作的错误都限定到当前弹窗就地显示，不再被遮罩层挡住。
- 客户长表单的服务端错误会自动聚焦并滚动到错误摘要；合同归档失败会在当前客户档案内就地显示。
- 表单成功提交后只关闭与该操作匹配的弹窗，避免无关操作触发弹窗关闭。

### 3.4 视觉与可访问性

- 三端可交互控件统一增加清晰的键盘焦点轮廓。
- 必填字段只在“缺失”时使用浅红提示；填写完成后恢复中性色，降低整页大面积绿色造成的视觉噪音。
- 警告、危险、成功状态重新统一颜色语义，修正少数危险状态误用普通/关闭色的问题。
- 舒适密度模式同步作用于弹窗控件、表格和字号；紧凑模式继续作为生产系统默认密度。
- 全局关闭动效能力保持有效。

## 五、需用户验收的交互点

按约定，本次没有替用户进行浏览器人工验收。建议验收时重点检查：

1. 打开报价列表，确认 100 条及以上报价仍能正常进入页面。
2. 创建报价填写一部分内容后关闭、刷新或点击其他导航，确认均有未保存提示。
3. 制造一次报价校验错误，确认错误显示在当前弹窗且输入不丢失；关闭后重新打开，不出现陈旧错误。
4. 在标记支持的报价表单中用 Enter 连续录入；确认下拉框、备注、文件上传和中文输入法不被误接管。
5. 提交期间确认关闭按钮不可用，提交成功后弹窗只关闭一次且无重复提交。
6. 用键盘 Tab 检查管理端、客户门户、仓库端焦点轮廓是否清晰一致。

## 六、边界与后续

- 本次已处理与当前故障同类的“单 SQL 绑定参数超限”和“单页面无界 D1 并发”问题。
- 极端超大配载批次还会受到账号套餐的单次 Worker 总查询额度、CPU 时间和数据规模影响；这属于容量规划问题，应在确定生产套餐与典型最大批次后单独做容量压测。
- 关联订单的轨迹派生状态只查找真正漂移的记录，当前订单优先、每次最多收敛 8 票；超大批次的其余漂移项会在后续访问时继续收敛，以避免一次请求耗尽 D1 额度。若生产中常见 8 票以上批次，后续应增加持久化后台任务队列。
- DOM 级弹窗、键盘与路由拦截行为目前由类型检查、生产构建和人工验收共同保障；仓库内现有 Vitest 使用 Node 环境，未引入新的浏览器测试运行时。
- 本次未执行远端迁移、部署或推送。
